# Phase 1 — Common Competitive Programming Operations

# Topic 1 — Sorting

Sorting is one of the most frequently used operations in Competitive Programming. Almost every contest language provides efficient library support (typically **O(n log n)**). Knowing the idiomatic syntax for each language saves both time and bugs during contests.

---

# 1. Ascending Sort

### Purpose

Sort elements in increasing order.

| Language       | Idiomatic CP Syntax                 | Library           | In-place | Complexity |
| -------------- | ----------------------------------- | ----------------- | -------- | ---------- |
| **C++**        | `sort(v.begin(), v.end());`         | STL `<algorithm>` | ✅        | O(n log n) |
| **Rust**       | `v.sort();`                         | std               | ✅        | O(n log n) |
| **Go**         | `slices.Sort(arr)` *(Go 1.21+)*     | `slices`          | ✅        | O(n log n) |
| **Java**       | `Arrays.sort(arr);`                 | JDK               | ✅        | O(n log n) |
| **Python**     | `arr.sort()`                        | built-in          | ✅        | O(n log n) |
| **JavaScript** | `arr.sort((a,b)=>a-b)`              | built-in          | ✅        | O(n log n) |
| **C#**         | `Array.Sort(arr);` / `list.Sort();` | .NET              | ✅        | O(n log n) |

### CP Recommendation

* Always use library sort.
* Never implement QuickSort manually unless required.

### Common Mistakes

| Language   | Mistake                                         |
| ---------- | ----------------------------------------------- |
| JavaScript | `arr.sort()` sorts lexicographically.           |
| Python     | Using `sorted()` unintentionally copies data.   |
| Java       | Sorting `Integer[]` when `int[]` is sufficient. |

# 2. Descending Sort

### Purpose

Sort largest to smallest.

| Language       | Idiomatic CP Syntax                                                 |     |             |
| -------------- | ------------------------------------------------------------------- | --- | ----------- |
| **C++**        | `sort(v.begin(), v.end(), greater<>());`                            |     |             |
| **Rust**       | `v.sort_by(                                                         | a,b | b.cmp(a));` |
| **Go**         | `slices.SortFunc(arr, func(a,b int) int { return b-a })`            |     |             |
| **Java**       | `Arrays.sort(objArr, Collections.reverseOrder());` *(objects only)* |     |             |
| **Python**     | `arr.sort(reverse=True)`                                            |     |             |
| **JavaScript** | `arr.sort((a,b)=>b-a)`                                              |     |             |
| **C#**         | `Array.Sort(arr); Array.Reverse(arr);` or custom comparer           |     |             |

### CP Recommendation

* Python provides the cleanest API.
* Java primitive arrays require extra work.

### Complexity

* **Time:** O(n log n)
* **Space:** Depends on implementation.

# 3. Stable Sort

### Purpose

Preserve relative order of equal elements.

Useful for:

* Multi-key sorting
* Offline queries
* Stable ranking

| Language   | Syntax                    | Stable? |
| ---------- | ------------------------- | ------- |
| C++        | `stable_sort(...)`        | ✅       |
| Rust       | `sort()`                  | ✅       |
| Go         | `slices.SortStableFunc()` | ✅       |
| Java       | `Arrays.sort(Object[])`   | ✅       |
| Python     | `sort()`                  | ✅       |
| JavaScript | Modern engines            | ✅       |
| C#         | `OrderBy()`               | ✅       |

### Complexity

Usually

* Time: O(n log n)
* Extra Space: O(n)

### CP Recommendation

Only use stable sorting when equality order matters.

# 4. Custom Comparator

### Purpose

Sort according to custom logic.

Examples:

* interval end
* pair second
* string length
* absolute value

| Language   | Example                                                                   |     |                  |
| ---------- | ------------------------------------------------------------------------- | --- | ---------------- |
| C++        | `sort(v.begin(),v.end(),[](auto&a,auto&b){ return a.second<b.second; });` |     |                  |
| Rust       | `v.sort_by(                                                               | a,b | a.1.cmp(&b.1));` |
| Go         | `slices.SortFunc(v, func(a,b Pair) int { return a.y-b.y })`               |     |                  |
| Java       | `Arrays.sort(arr,(a,b)->a.y-b.y);`                                        |     |                  |
| Python     | `arr.sort(key=lambda x:x[1])`                                             |     |                  |
| JavaScript | `arr.sort((a,b)=>a.y-b.y)`                                                |     |                  |
| C#         | `list.Sort((a,b)=>a.Y.CompareTo(b.Y));`                                   |     |                  |

### CP Recommendation

Prefer comparators instead of transforming data manually.

# 5. Sort by Key

### Purpose

Sort using a derived property.

Examples

* string length
* second element
* frequency
* absolute value

| Language   | Example                   |   |           |
| ---------- | ------------------------- | - | --------- |
| C++        | Comparator                |   |           |
| Rust       | `sort_by_key(             | x | x.len())` |
| Go         | Comparator                |   |           |
| Java       | Comparator.comparing(...) |   |           |
| Python     | `key=len`                 |   |           |
| JavaScript | Comparator                |   |           |
| C#         | `OrderBy(x=>x.Length)`    |   |           |

### Example

Sort strings by length.

Python

```python
arr.sort(key=len)
```

Rust

```rust
v.sort_by_key(|s| s.len());
```

# 6. Partial Sort

### Purpose

Sort only the smallest or largest **k** elements.

Useful for

* Top K
* K smallest
* Selection problems

| Language   | Recommended                 |
| ---------- | --------------------------- |
| C++        | `partial_sort()`            |
| Rust       | `select_nth_unstable()`     |
| Go         | Use heap or QuickSelect     |
| Java       | PriorityQueue / QuickSelect |
| Python     | `heapq.nsmallest()`         |
| JavaScript | Heap / QuickSelect          |
| C#         | PriorityQueue / manual      |

### Notes

Only C++ has an excellent built-in partial sort.

### Complexity

C++

```
O(n log k)
```

# 7. Sort Copy vs In-place

### Purpose

Know whether sorting modifies the original collection.

| Language   | In-place        | Returns Copy               |
| ---------- | --------------- | -------------------------- |
| C++        | `sort()`        | copy manually              |
| Rust       | `sort()`        | clone first                |
| Go         | `slices.Sort()` | copy first                 |
| Java       | `Arrays.sort()` | copy first                 |
| Python     | `sort()`        | `sorted()`                 |
| JavaScript | `sort()`        | `toSorted()` *(modern JS)* |
| C#         | `Sort()`        | `OrderBy().ToList()`       |

### Python

```python
b = sorted(a)
```

Original remains unchanged.

### JavaScript

```javascript
let b = arr.toSorted((a,b)=>a-b)
```

Original unchanged.

# CP Recommendations

* ✅ Always use the language's standard sorting library.
* ✅ Use **ascending sort** unless the problem explicitly needs descending order.
* ✅ Prefer **key-based sorting** (Python/Rust/Java) over writing verbose comparators when available.
* ✅ Use **stable sort** only when preserving the order of equal elements matters.
* ✅ For **Top-K** or **K smallest/largest**, avoid fully sorting the array; use **partial sort**, **heap**, or **QuickSelect** depending on language support.
* ✅ In JavaScript, always provide a numeric comparator for numbers (`(a, b) => a - b`).
* ✅ In Python, use `sorted()` when you need to preserve the original array; otherwise `list.sort()` is more memory-efficient.
* ✅ In Java, prefer primitive arrays (`int[]`) over boxed types (`Integer[]`) unless a custom comparator is required.
* ✅ In contests, avoid implementing your own sorting algorithm unless the problem specifically requires it.
