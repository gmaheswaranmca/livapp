# Phase 1 — Common Competitive Programming Operations

# Topic 12 — Unique / Deduplication

Removing duplicate elements is a common requirement in Competitive Programming. It is used in:

* Coordinate Compression
* Graph preprocessing
* Frequency counting
* Set operations
* Sliding Window
* Hashing
* Sorting-based algorithms

The appropriate technique depends on whether:

* Order must be preserved
* Sorting is allowed
* Only distinct values are needed

---

# 1. Remove Duplicates

## Purpose

Remove duplicate values from a collection.

Example

```text
Input

3 1 2 3 2 1 4

↓

Output

3 1 2 4
```

(order preserved)

| Language       | Idiomatic CP Approach           | Built-in | Time     | Space |
| -------------- | ------------------------------- | -------- | -------- | ----- |
| **C++**        | `unordered_set` + output vector | Partial  | O(n) avg | O(n)  |
| **Rust**       | `HashSet` + output vector       | Partial  | O(n) avg | O(n)  |
| **Go**         | `map[T]bool`                    | ❌        | O(n) avg | O(n)  |
| **Java**       | `HashSet` + `ArrayList`         | Partial  | O(n) avg | O(n)  |
| **Python**     | `dict.fromkeys(arr)`            | ✅        | O(n) avg | O(n)  |
| **JavaScript** | `new Set(arr)`*                 | ✅        | O(n) avg | O(n)  |
| **C#**         | `HashSet<T>`                    | Partial  | O(n) avg | O(n)  |

* `Set` preserves insertion order in modern JavaScript.

### CP Recommendation

When order matters, use a **Hash Set + output list/vector** (or the language's insertion-order-preserving feature where available).

# 2. Keep Original Order

## Purpose

Remove duplicates **without changing the order** of first occurrences.

Example

```text
Input

5 2 5 3 2 4

↓

5 2 3 4
```

### Standard Algorithm

```text
visited = empty set

for each x

    if x not in visited

        output x

        visited.add(x)
```

### Complexity

| Time         | Space |
| ------------ | ----- |
| O(n) average | O(n)  |

### Language Notes

| Language   | Recommended                                   |
| ---------- | --------------------------------------------- |
| C++        | `unordered_set`                               |
| Rust       | `HashSet`                                     |
| Go         | `map`                                         |
| Java       | `LinkedHashSet` (if directly storing results) |
| Python     | `dict.fromkeys()`                             |
| JavaScript | `Set`                                         |
| C#         | `HashSet` + result list                       |

### CP Recommendation

This is the preferred technique unless the problem explicitly allows reordering.

---

# 3. Sort then Unique

## Purpose

Remove duplicates when preserving order is **not** required.

Example

```text
Input

5 3 2 5 1 3

↓

Sort

1 2 3 3 5 5

↓

Unique

1 2 3 5
```

### Built-in Support

| Language       | Idiomatic CP Syntax                     |
| -------------- | --------------------------------------- |
| **C++**        | `sort()` + `erase(unique(), end)`       |
| **Rust**       | `sort(); dedup();`                      |
| **Go**         | `slices.Sort()` + manual unique         |
| **Java**       | `Arrays.sort()` + manual                |
| **Python**     | `sorted(set(arr))`                      |
| **JavaScript** | `Array.from(new Set(arr.sort(...)))`    |
| **C#**         | `Array.Sort()` + manual or `Distinct()` |

### Complexity

| Step                       | Time       |
| -------------------------- | ---------- |
| Sort                       | O(n log n) |
| Remove Adjacent Duplicates | O(n)       |
| Total                      | O(n log n) |

### CP Recommendation

This is the standard approach for:

* Coordinate Compression
* Interval merging
* Sweep Line algorithms
* Offline processing

# 4. Distinct Values

## Purpose

Obtain the collection of unique values (order usually unimportant).

Example

```text
Input

2 3 2 5 5 1

↓

1 2 3 5
```

### Recommended Containers

| Language       | Container               |
| -------------- | ----------------------- |
| **C++**        | `unordered_set` / `set` |
| **Rust**       | `HashSet` / `BTreeSet`  |
| **Go**         | `map[T]struct{}`        |
| **Java**       | `HashSet` / `TreeSet`   |
| **Python**     | `set`                   |
| **JavaScript** | `Set`                   |
| **C#**         | `HashSet<T>`            |

### Complexity

| Container   | Insert   | Lookup   |
| ----------- | -------- | -------- |
| Hash Set    | O(1) avg | O(1) avg |
| Ordered Set | O(log n) | O(log n) |

### CP Recommendation

* Use **Hash Set** when ordering does not matter.
* Use **Ordered Set** only if sorted iteration is required.

---

# Hash Set vs Sort + Unique

| Feature                  | Hash Set                                             | Sort + Unique                         |
| ------------------------ | ---------------------------------------------------- | ------------------------------------- |
| Preserves Original Order | Only with auxiliary output (or insertion-order sets) | ❌                                     |
| Returns Sorted Values    | ❌                                                    | ✅                                     |
| Average Time             | O(n)                                                 | O(n log n)                            |
| Extra Memory             | O(n)                                                 | O(1)–O(n)*                            |
| Best For                 | Membership, deduplication                            | Coordinate compression, sorted output |

* Depends on sorting implementation.

# CP Recommendations

* ✅ If **original order must be preserved**, use a **Hash Set + output collection** (or `dict.fromkeys()` in Python, `Set` in JavaScript, `LinkedHashSet` in Java).
* ✅ If **sorted output** is required, use **sort + unique** instead of a hash set.
* ✅ For **coordinate compression**, the standard approach is:

  1. Copy values
  2. Sort
  3. Remove duplicates
* ✅ Prefer **Hash Set** over **Ordered Set** unless sorted iteration is explicitly needed.
* ✅ In C++, remember that `std::unique()` **only removes adjacent duplicates**—sorting is required first unless duplicates are already consecutive.

---

# Common Mistakes

| Mistake                                         | Why It Happens                                   | Better Approach                                                   |
| ----------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------- |
| Calling `unique()` on an unsorted vector        | `unique()` only removes consecutive duplicates   | Sort first or use a hash set                                      |
| Using a `set` when original order matters       | Sets reorder elements                            | Use a hash set with an output list (or insertion-order structure) |
| Assuming Python `set` preserves insertion order | Only `dict` has a language guarantee             | Use `dict.fromkeys()` for stable deduplication                    |
| Forgetting that hash sets discard ordering      | Iteration order is unspecified in many languages | Use an ordered structure if needed                                |
| Using an ordered set unnecessarily              | Slower `O(log n)` operations                     | Prefer a hash set when order is irrelevant                        |

---

## Choosing the Right Deduplication Technique

| Scenario                                  | Best Choice                  |
| ----------------------------------------- | ---------------------------- |
| Remove duplicates and keep original order | Hash Set + output collection |
| Remove duplicates and sort                | Sort + Unique                |
| Need only distinct values                 | Hash Set                     |
| Need sorted distinct values               | Ordered Set or Sort + Unique |
| Coordinate Compression                    | Sort + Unique                |
| Fast membership checks                    | Hash Set                     |
