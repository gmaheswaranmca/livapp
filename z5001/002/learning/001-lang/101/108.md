# Phase 1 — Common Competitive Programming Operations

# Topic 8 — Sum / Accumulation

Accumulation combines elements of a collection into a single result. Besides summation, it includes:

* Product
* Prefix accumulation
* Running sum
* XOR accumulation
* Custom aggregation

These operations are fundamental in Prefix Sum, Dynamic Programming, Bit Manipulation, and Greedy algorithms.

---

# 1. Sum

## Purpose

Compute the sum of all elements.

Example

```text
Array

3 5 2 7

↓

17
```

| Language       | Idiomatic CP Syntax           | Built-in        | Time | Space |
| -------------- | ----------------------------- | --------------- | ---- | ----- |
| **C++**        | `accumulate(begin, end, 0LL)` | STL `<numeric>` | O(n) | O(1)  |
| **Rust**       | `iter().sum::<i64>()`         | std             | O(n) | O(1)  |
| **Go**         | Manual loop                   | ❌               | O(n) | O(1)  |
| **Java**       | Manual loop                   | ❌               | O(n) | O(1)  |
| **Python**     | `sum(arr)`                    | built-in        | O(n) | O(1)  |
| **JavaScript** | `arr.reduce((s,x)=>s+x,0)`    | built-in        | O(n) | O(1)  |
| **C#**         | `arr.Sum()` *(LINQ)*          | ✅               | O(n) | O(1)  |

### CP Recommendation

* In C++, use `0LL` when summing integers that may exceed 32-bit range.
* In Java and Go, a manual loop is the fastest and most common CP solution.

### Common Mistakes

* Integer overflow by using `int` instead of `long long` / `long`.
* Forgetting the initial value in `reduce()`.

# 2. Product

## Purpose

Compute the product of all elements.

Example

```text
2 3 4

↓

24
```

| Language       | Idiomatic CP Syntax                        |
| -------------- | ------------------------------------------ |
| **C++**        | `accumulate(begin,end,1LL,multiplies<>())` |
| **Rust**       | `iter().product::<i64>()`                  |
| **Go**         | Manual loop                                |
| **Java**       | Manual loop                                |
| **Python**     | `math.prod(arr)`                           |
| **JavaScript** | `reduce((p,x)=>p*x,1)`                     |
| **C#**         | Manual loop / `Aggregate()`                |

### Complexity

* **Time:** O(n)
* **Space:** O(1)

### CP Recommendation

Be careful of overflow. Many problems require taking the product modulo a given value.

# 3. Prefix Accumulation (Prefix Sum)

## Purpose

Precompute cumulative values for efficient range queries.

Example

```text
Array

2 4 1 5

Prefix Sum

2 6 7 12
```

Range sum:

```text
Sum(l..r)

=

prefix[r] - prefix[l-1]
```

| Language       | Typical Approach                  |
| -------------- | --------------------------------- |
| **C++**        | `partial_sum()` or manual         |
| **Rust**       | Manual                            |
| **Go**         | Manual                            |
| **Java**       | Manual                            |
| **Python**     | Manual / `itertools.accumulate()` |
| **JavaScript** | Manual                            |
| **C#**         | Manual                            |

### Complexity

| Build | Query |
| ----- | ----- |
| O(n)  | O(1)  |

### CP Recommendation

One of the most important preprocessing techniques in Competitive Programming.

Typical problems:

* Range Sum Query
* Difference Arrays
* Prefix XOR
* Prefix Frequency
* 2D Prefix Sum

# 4. Running Sum

## Purpose

Generate cumulative totals while iterating.

Example

```text
1 2 3 4

↓

1 3 6 10
```

Unlike prefix sums used for queries, running sums are often produced as output or used during a single pass.

| Language       | Idiomatic CP Syntax      |
| -------------- | ------------------------ |
| **C++**        | `partial_sum()`          |
| **Rust**       | Manual                   |
| **Go**         | Manual                   |
| **Java**       | Manual                   |
| **Python**     | `itertools.accumulate()` |
| **JavaScript** | Manual                   |
| **C#**         | Manual                   |

### Complexity

* Time: **O(n)**
* Space: **O(n)** if storing all running sums

# 5. XOR Accumulation

## Purpose

Accumulate values using the XOR operator.

Example

```text
1 2 3

↓

1 ^ 2 ^ 3 = 0
```

Common uses:

* Find single non-duplicate
* Missing number
* Bit manipulation
* Prefix XOR
* Trie XOR problems

| Language       | Typical Approach                                   |     |         |
| -------------- | -------------------------------------------------- | --- | ------- |
| **C++**        | `accumulate(...,0,bit_xor<>())` or manual          |     |         |
| **Rust**       | `fold(0,                                           | a,b | a ^ b)` |
| **Go**         | Manual                                             |     |         |
| **Java**       | Manual                                             |     |         |
| **Python**     | `functools.reduce(operator.xor, arr, 0)` or manual |     |         |
| **JavaScript** | `reduce((a,b)=>a^b,0)`                             |     |         |
| **C#**         | Manual / `Aggregate()`                             |     |         |

### Complexity

* Time: **O(n)**
* Space: **O(1)**

### CP Recommendation

A simple manual loop is usually the clearest and fastest approach across all languages.

# CP Recommendations

* ✅ Use built-in summation APIs where they are concise and efficient.
* ✅ In C++, initialize `accumulate()` with `0LL` (or `0L` for larger types) to avoid 32-bit overflow.
* ✅ For range sum queries, preprocess a **Prefix Sum** array once in **O(n)** and answer each query in **O(1)**.
* ✅ For repeated XOR range queries, build a **Prefix XOR** array using the same idea as Prefix Sum.
* ✅ Use modular arithmetic when products can exceed integer limits.
* ✅ Prefer manual loops in Go and Java—they are idiomatic, efficient, and avoid unnecessary abstraction.

---

# Common Mistakes

| Mistake                                                     | Why It Happens                      | Better Approach                                           |
| ----------------------------------------------------------- | ----------------------------------- | --------------------------------------------------------- |
| Using `int` for large sums                                  | Integer overflow                    | Use `long long`, `long`, or equivalent                    |
| Forgetting the initial value in `accumulate()` / `reduce()` | Incorrect results or type inference | Always provide the identity value (`0`, `1`, etc.)        |
| Recomputing range sums repeatedly                           | O(n) per query                      | Use Prefix Sum preprocessing                              |
| Using multiplication without modulo                         | Overflow in combinatorics and DP    | Apply modulo after each multiplication                    |
| Building Prefix Sum with off-by-one indexing                | Incorrect query results             | Use a consistent indexing convention (0-based or 1-based) |

---

## Choosing the Right Accumulation Technique

| Scenario                  | Best Choice                                                  |
| ------------------------- | ------------------------------------------------------------ |
| Sum all elements          | `sum()` / `accumulate()` / manual loop                       |
| Multiply all elements     | Product accumulation                                         |
| Many range sum queries    | Prefix Sum                                                   |
| Running cumulative totals | Running Sum                                                  |
| XOR aggregation           | XOR accumulation                                             |
| Range XOR queries         | Prefix XOR                                                   |
| Custom aggregation        | `fold()` / `reduce()` / `accumulate()` with custom operation |
