# Phase 1 — Common Competitive Programming Operations

# Topic 3 — Rotation

Rotation shifts elements circularly without changing their relative order. It is frequently used in Competitive Programming for:

* Circular arrays
* Ring buffers
* String rotation problems
* Array manipulation
* Sliding window on circular arrays
* Reverse algorithm
* Queue simulation

Unlike reversing, built-in rotation support varies significantly across languages.

---

# 1. Left Rotate

## Purpose

Move the first **k** elements to the end.

Example

```text
Array
1 2 3 4 5 6

Left Rotate by 2

↓

3 4 5 6 1 2
```

| Language       | Idiomatic CP Syntax                           | Built-in | In-place | Time | Space |
| -------------- | --------------------------------------------- | -------- | -------- | ---- | ----- |
| **C++**        | `rotate(v.begin(), v.begin()+k, v.end())`     | STL      | ✅        | O(n) | O(1)  |
| **Rust**       | `v.rotate_left(k)`                            | std      | ✅        | O(n) | O(1)  |
| **Go**         | Manual / Reverse Algorithm                    | ❌        | ✅        | O(n) | O(1)  |
| **Java**       | Manual / Reverse Algorithm                    | ❌        | ✅        | O(n) | O(1)  |
| **Python**     | `collections.deque.rotate(-k)` *(deque only)* | Partial  | ✅        | O(n) |       |
| **JavaScript** | Manual                                        | ❌        | ✅        | O(n) |       |
| **C#**         | Manual                                        | ❌        | ✅        | O(n) |       |

### CP Recommendation

* C++ and Rust have excellent built-in support.
* For arrays in most languages, use the **Reverse Algorithm**.

---

# 2. Right Rotate

## Purpose

Move the last **k** elements to the front.

Example

```text
1 2 3 4 5 6

Right Rotate by 2

↓

5 6 1 2 3 4
```

| Language       | Idiomatic CP Syntax                     |
| -------------- | --------------------------------------- |
| **C++**        | `rotate(v.begin(), v.end()-k, v.end())` |
| **Rust**       | `v.rotate_right(k)`                     |
| **Go**         | Manual                                  |
| **Java**       | Manual                                  |
| **Python**     | `deque.rotate(k)`                       |
| **JavaScript** | Manual                                  |
| **C#**         | Manual                                  |

### Complexity

* **Time:** O(n)
* **Space:** O(1)

### Common Mistake

Forgetting to normalize:

```text
k %= n
```

Otherwise, `k > n` produces incorrect results or errors.

# 3. Rotate Subrange

## Purpose

Rotate only part of a collection while leaving the rest unchanged.

Example

```text
Original

1 2 3 4 5 6 7

Rotate subrange [2..6) left by 2

↓

1 2 5 6 3 4 7
```

| Language       | Built-in                      | Notes                    |
| -------------- | ----------------------------- | ------------------------ |
| **C++**        | ✅ `rotate(first,middle,last)` | Very flexible            |
| **Rust**       | Slice rotation                | `v[l..r].rotate_left(k)` |
| **Go**         | Manual                        | Reverse Algorithm        |
| **Java**       | Manual                        | Reverse Algorithm        |
| **Python**     | Manual slice assignment       |                          |
| **JavaScript** | Manual                        |                          |
| **C#**         | Manual                        |                          |

### CP Recommendation

Subrange rotation is useful in:

* Rope problems
* Sequence editing
* Interval manipulation

# 4. Reverse Algorithm (Rotation Using Three Reversals)

## Purpose

Rotate an array **in-place** using only reverse operations.

Applicable to **all languages**.

### Left Rotate by k

```text
Reverse first k

Reverse remaining n-k

Reverse entire array
```

Example

```text
1 2 3 4 5 6

Reverse first 2

2 1 3 4 5 6

Reverse remaining

2 1 6 5 4 3

Reverse whole

3 4 5 6 1 2
```

### Right Rotate by k

```text
Reverse first n-k

Reverse last k

Reverse entire array
```

### Complexity

| Time | Space |
| ---- | ----- |
| O(n) | O(1)  |

### CP Recommendation

This is the standard interview and CP solution when no built-in rotation API exists.

# 5. Circular Indexing

## Purpose

Treat an array as circular without physically rotating it.

Instead of moving elements, compute wrapped indices.

Example

```text
Array

10 20 30 40 50

Current index = 4

Next index

(4 + 1) % 5 = 0

Previous index

(4 - 1 + 5) % 5 = 3
```

### Common Formulas

| Operation        | Formula           |
| ---------------- | ----------------- |
| Next             | `(i + 1) % n`     |
| Previous         | `(i - 1 + n) % n` |
| Left shift by k  | `(i + k) % n`     |
| Right shift by k | `(i - k + n) % n` |

### Languages

Exactly the same in:

* C++
* Rust
* Go
* Java
* Python
* JavaScript
* C#

### CP Uses

* Circular queues
* Josephus problem
* Circular arrays
* Sliding Window II
* Ring buffers
* Clock problems

### Common Mistakes

* Using `(i - 1) % n` directly in languages where `%` can yield a negative result (e.g., C++, Java, JavaScript, C#). Use `(i - 1 + n) % n` instead.
* Forgetting to normalize `k` with `k %= n`.

# CP Recommendations

* ✅ Prefer built-in rotation APIs in C++ (`std::rotate`) and Rust (`rotate_left`/`rotate_right`).
* ✅ For languages without rotation support, use the **three-reversal algorithm** for an in-place **O(n)** solution.
* ✅ Normalize rotations using `k %= n` before performing any operation.
* ✅ Prefer **circular indexing** when you only need logical rotation; it avoids unnecessary data movement.
* ✅ Use `collections.deque.rotate()` in Python only when working with deques, not lists.
* ✅ For repeated rotations, maintain an offset and compute indices using modular arithmetic instead of rotating the array each time.

---

# Common Mistakes

| Mistake                                   | Why It Happens                        | Better Approach                                   |
| ----------------------------------------- | ------------------------------------- | ------------------------------------------------- |
| Forgetting `k %= n`                       | Large rotations                       | Normalize first                                   |
| Physically rotating for every query       | Inefficient for many operations       | Maintain a rotation offset                        |
| Using negative modulo directly            | Negative results in several languages | Use `(i - k + n) % n`                             |
| Using `deque.rotate()` on lists in Python | API confusion                         | Convert to `deque` or use slicing/manual rotation |
| Allocating extra arrays unnecessarily     | Simpler but slower                    | Prefer in-place reversal when possible            |
