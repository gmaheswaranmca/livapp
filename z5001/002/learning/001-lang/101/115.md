# Phase 1 — Common Competitive Programming Operations

# Topic 15 — Set Operations

Set operations work on collections of **unique values** and are frequently used in Competitive Programming for:

* Common elements
* Distinct values
* Coordinate compression
* Graph problems
* Number theory
* Offline queries
* Bitset techniques

The classical set operations are:

* Union
* Intersection
* Difference
* Symmetric Difference

For **sorted collections**, most languages use the **two-pointer technique**. For **unsorted collections**, hash sets are usually preferred.

---

# 1. Union

## Purpose

Return all distinct elements from both collections.

Example

```text id="y6f4kt"
A

1 2 4

B

2 3 4 5

↓

1 2 3 4 5
```

### Recommended Approaches

| Input Type | Best Method  | Complexity     |
| ---------- | ------------ | -------------- |
| Sorted     | Two pointers | O(n+m)         |
| Unsorted   | Hash Set     | O(n+m) average |

| Language       | Idiomatic CP Syntax         | Built-in |
| -------------- | --------------------------- | -------- |
| **C++**        | `set_union()` (sorted)      | ✅        |
| **Rust**       | `HashSet::union()` / manual | Partial  |
| **Go**         | `map[T]struct{}`            | ❌        |
| **Java**       | `HashSet.addAll()`          | ✅        |
| **Python**     | `set1 \| set2`              | ✅        |
| **JavaScript** | `new Set([...a, ...b])`     | Partial  |
| **C#**         | `HashSet.UnionWith()`       | ✅        |

### Complexity

| Method       | Time       | Space  |
| ------------ | ---------- | ------ |
| Two Pointers | O(n+m)     | O(n+m) |
| Hash Set     | O(n+m) avg | O(n+m) |

### CP Recommendation

If the inputs are already sorted, do **not** convert them into hash sets—use two pointers.

---

# 2. Intersection

## Purpose

Return elements present in **both** collections.

Example

```text id="1gqavj"
A

1 2 4 5

B

2 3 4

↓

2 4
```

### Recommended Approaches

| Input    | Method       |
| -------- | ------------ |
| Sorted   | Two pointers |
| Unsorted | Hash Set     |

| Language       | Idiomatic CP Syntax       |
| -------------- | ------------------------- |
| **C++**        | `set_intersection()`      |
| **Rust**       | `HashSet::intersection()` |
| **Go**         | Hash map lookup           |
| **Java**       | `retainAll()`             |
| **Python**     | `set1 & set2`             |
| **JavaScript** | `filter()` + `Set`        |
| **C#**         | `IntersectWith()`         |

### Complexity

* Sorted: **O(n+m)**
* Hash Set: **O(n+m)** average

### CP Recommendation

Hash sets are usually faster than nested loops for unsorted inputs.

---

# 3. Difference

## Purpose

Return elements present in the first collection but **not** in the second.

Example

```text id="2lz4zy"
A

1 2 3 4

B

2 4

↓

1 3
```

### Recommended Approaches

| Language       | Idiomatic CP Syntax     |
| -------------- | ----------------------- |
| **C++**        | `set_difference()`      |
| **Rust**       | `HashSet::difference()` |
| **Go**         | Hash map                |
| **Java**       | `removeAll()`           |
| **Python**     | `set1 - set2`           |
| **JavaScript** | `filter()`              |
| **C#**         | `ExceptWith()`          |

### Complexity

* O(n+m)

### CP Recommendation

Difference is directional:

```text id="u91c9q"
A - B

≠

B - A
```

---

# 4. Symmetric Difference

## Purpose

Return elements present in **exactly one** collection.

Example

```text id="imwccm"
A

1 2 3

B

3 4 5

↓

1 2 4 5
```

### Mathematical Definition

```text id="z8kqcs"
(A − B)

∪

(B − A)
```

### Language Support

| Language       | Idiomatic CP Syntax               |
| -------------- | --------------------------------- |
| **C++**        | `set_symmetric_difference()`      |
| **Rust**       | `HashSet::symmetric_difference()` |
| **Go**         | Manual                            |
| **Java**       | Manual                            |
| **Python**     | `set1 ^ set2`                     |
| **JavaScript** | Manual                            |
| **C#**         | `SymmetricExceptWith()`           |

### Complexity

* O(n+m)

# Hash Set vs Two-Pointer Set Operations

| Feature                | Two Pointers  | Hash Set      |
| ---------------------- | ------------- | ------------- |
| Inputs Must Be Sorted  | ✅             | ❌             |
| Time                   | O(n+m)        | O(n+m) avg    |
| Extra Memory           | O(1)*         | O(n)          |
| Preserves Sorted Order | ✅             | ❌             |
| Best For               | Sorted arrays | Unsorted data |

* Excluding the output collection.

# CP Recommendations

* ✅ Use the **two-pointer technique** when both inputs are already sorted—it is memory-efficient and preserves sorted order.
* ✅ Use **Hash Sets** for unsorted inputs and repeated membership queries.
* ✅ Remember that **difference is directional** (`A - B` is different from `B - A`).
* ✅ Prefer built-in set operations where available, but know the underlying two-pointer algorithm since many CP problems use arrays rather than set containers.
* ✅ If duplicates matter, classical set operations are **not sufficient**—use frequency maps (multisets) instead.
* ✅ Avoid converting already sorted arrays into hash sets unless constant-time membership is specifically needed later.

---

# Common Mistakes

| Mistake                                   | Why It Happens                           | Better Approach                              |
| ----------------------------------------- | ---------------------------------------- | -------------------------------------------- |
| Applying `set_union()` to unsorted ranges | STL set algorithms require sorted inputs | Sort first or use hash sets                  |
| Forgetting that sets remove duplicates    | Set semantics                            | Use frequency maps when multiplicity matters |
| Confusing `A - B` with `B - A`            | Difference is directional                | Verify operand order                         |
| Using nested loops for intersection       | O(n²) complexity                         | Use two pointers or hash sets                |
| Expecting hash set iteration to be sorted | Hash sets are unordered                  | Use ordered sets or sort the result          |

---

## Choosing the Right Set Operation

| Scenario                              | Best Choice              |
| ------------------------------------- | ------------------------ |
| Combine distinct elements             | Union                    |
| Find common elements                  | Intersection             |
| Elements only in the first collection | Difference (`A - B`)     |
| Elements in exactly one collection    | Symmetric Difference     |
| Inputs already sorted                 | Two-pointer algorithms   |
| Inputs unsorted                       | Hash Set                 |
| Duplicates must be preserved          | Frequency Map / Multiset |
