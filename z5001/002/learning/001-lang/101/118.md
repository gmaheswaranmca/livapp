# Phase 1 — Common Competitive Programming Operations

# Topic 18 — Selection Algorithms

Selection algorithms find the **k-th smallest**, **k-th largest**, **median**, or another order statistic **without fully sorting** the collection.

They are frequently used in:

* Median problems
* Top-K queries
* K Closest Points
* Kth Largest Element
* Streaming problems
* QuickSelect
* Partition-based algorithms

> **Key Idea:** If you only need the **k-th** element, don't sort the entire array (`O(n log n)`). Use a selection algorithm instead.

---

# 1. `nth_element`

## Purpose

Rearrange the collection so that the element at position **k** is the same as it would be in sorted order.

After execution:

* Elements before `k` are **≤** the k-th element.
* Elements after `k` are **≥** the k-th element.
* The two partitions are **not sorted**.

Example

```text id="93m5yx"
Input

7 2 5 1 8 4

k = 2

Possible Result

2 1 4 7 8 5

        ↑

3rd smallest
```

Only the highlighted element is guaranteed to be in its final sorted position.

| Language       | Built-in                          | Recommended |
| -------------- | --------------------------------- | ----------- |
| **C++**        | `nth_element()`                   | ✅           |
| **Rust**       | `select_nth_unstable()`           | ✅           |
| **Go**         | Manual QuickSelect                | ❌           |
| **Java**       | Manual QuickSelect                | ❌           |
| **Python**     | `heapq.nsmallest()` / QuickSelect | Partial     |
| **JavaScript** | Manual QuickSelect                | ❌           |
| **C#**         | Manual QuickSelect                | ❌           |

### Complexity

| Case    | Time   |
| ------- | ------ |
| Average | O(n)   |
| Worst   | O(n²)* |

* Practical implementations are highly optimized and rarely hit the worst case.

### CP Recommendation

If your language provides `nth_element()` or `select_nth_unstable()`, use it instead of sorting.

# 2. QuickSelect

## Purpose

Find the **k-th smallest** element using repeated partitioning.

It is based on the same partition idea as QuickSort.

### Algorithm

```text id="fijc1w"
Choose pivot

↓

Partition

↓

If pivot index == k

    Answer found

Else

    Recurse into one side only
```

Unlike QuickSort, only **one partition** is processed.

Example

```text id="0u5gdz"
Array

7 2 9 4 1

k = 2

↓

Answer = 4
```

### Complexity

| Case    | Time  |
| ------- | ----- |
| Average | O(n)  |
| Worst   | O(n²) |

### Space

* Iterative: **O(1)**
* Recursive: **O(log n)** average

### CP Recommendation

Randomized pivot selection greatly improves expected performance.

# 3. Median

## Purpose

Find the middle element(s) of a collection.

Example

```text id="9mjlwm"
1 3 5 8 9

↓

Median

5
```

Even-sized example

```text id="5u4ew1"
1 3 5 8

↓

Middle Elements

3

5
```

### Methods

| Requirement         | Recommended                 |
| ------------------- | --------------------------- |
| One-time median     | QuickSelect / `nth_element` |
| Running median      | Two Heaps                   |
| Fully sorted output | Sort                        |

### Complexity

| Method        | Time         |
| ------------- | ------------ |
| Sort          | O(n log n)   |
| QuickSelect   | O(n) average |
| `nth_element` | O(n) average |

### CP Recommendation

For a single median query, avoid sorting if only the median is needed.

# 4. Kth Smallest

## Purpose

Find the k-th smallest element.

Example

```text id="8hbmd6"
Array

8 2 5 1 7

k = 3

↓

5
```

### Common Methods

| Method            | Complexity |
| ----------------- | ---------- |
| Sort              | O(n log n) |
| QuickSelect       | O(n) avg   |
| `nth_element`     | O(n) avg   |
| Max Heap (size k) | O(n log k) |

### Language Recommendations

| Language  | Preferred               |
| --------- | ----------------------- |
| C++       | `nth_element()`         |
| Rust      | `select_nth_unstable()` |
| Others    | QuickSelect             |
| Streaming | Max Heap                |

### CP Recommendation

For streaming or online data, maintain a **Max Heap of size `k`**.

---

# 5. Kth Largest

## Purpose

Find the k-th largest element.

Example

```text id="rnrhvj"
Array

8 2 5 1 7

k = 2

↓

7
```

### Common Methods

| Method            | Complexity |
| ----------------- | ---------- |
| Sort descending   | O(n log n) |
| Min Heap (size k) | O(n log k) |
| QuickSelect       | O(n) avg   |
| `nth_element`     | O(n) avg   |

### Heap Idea

```text id="4emrvv"
Maintain

Min Heap

of size k

↓

Top

=

k-th largest
```

### CP Recommendation

For Top-K Largest problems, the heap solution is often simpler than QuickSelect.

# Selection Method Comparison

| Method        | Time       | Extra Space | Sorted Output | Best For                    |
| ------------- | ---------- | ----------- | ------------- | --------------------------- |
| Full Sort     | O(n log n) | O(1)–O(n)   | ✅             | Need all elements sorted    |

| Heap          | O(n log k) | O(k)        | ❌             | Streaming, Top-K            |

# CP Recommendations

* ✅ If you only need the **k-th** element, do **not** sort the entire array.
* ✅ Use **`nth_element()`** (C++) or **`select_nth_unstable()`** (Rust) whenever available.
* ✅ Use **QuickSelect** in languages without a built-in selection algorithm.
* ✅ For **Top-K** or **streaming** problems, prefer a heap:

  * **Max Heap** for k-th smallest
  * **Min Heap** for k-th largest
* ✅ Randomize the pivot in QuickSelect to avoid poor performance on adversarial inputs.
* ✅ If multiple k-th queries are required on the same static array, sorting once may be more efficient overall.

---

# Common Mistakes

| Mistake                                      | Why It Happens              | Better Approach                                       |
| -------------------------------------------- | --------------------------- | ----------------------------------------------------- |
| Sorting to find a single k-th element        | Unnecessary O(n log n) work | Use QuickSelect or `nth_element`                      |
| Assuming `nth_element` fully sorts the array | It only partitions          | Sort only if full ordering is required                |
| Using QuickSelect on streaming input         | Requires random access      | Maintain a heap                                       |
| Choosing the wrong heap type                 | Incorrect order statistic   | Max Heap for k-th smallest, Min Heap for k-th largest |
| Forgetting zero-based vs one-based indexing  | Wrong answer                | Convert `k` consistently                              |

---

## Choosing the Right Selection Technique

| Scenario                         | Best Choice                                       |
| -------------------------------- | ------------------------------------------------- |
| One-time k-th smallest/largest   | `nth_element` / QuickSelect                       |
| Need all elements sorted         | Full Sort                                         |
| Running median                   | Two Heaps                                         |
| Streaming Top-K largest          | Min Heap (size `k`)                               |
| Streaming Top-K smallest         | Max Heap (size `k`)                               |
| Multiple order-statistic queries | Consider sorting once or advanced data structures |
