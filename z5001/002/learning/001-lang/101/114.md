# Phase 1 — Common Competitive Programming Operations

# Topic 14 — Merge

Merging combines two or more sorted collections into a larger sorted collection. It is a fundamental operation used in:

* Merge Sort
* Two Pointers
* External Sorting
* K-way Merge
* Interval Problems
* Priority Queue problems
* Divide & Conquer

Unlike concatenation, **merge assumes the inputs are already sorted**.

---

# 1. Merge Sorted Arrays

## Purpose

Merge two sorted arrays into one sorted array.

Example

```text id="e9k7ta"
A

1 3 5

B

2 4 6

↓

1 2 3 4 5 6
```

### Standard Algorithm

```text id="j9m4uv"
i = 0
j = 0

while both arrays have elements

    take smaller element

append remaining elements
```

| Language       | Idiomatic CP Syntax                              | Built-in | Time   | Space  |
| -------------- | ------------------------------------------------ | -------- | ------ | ------ |
| **C++**        | `merge(a.begin(),a.end(),b.begin(),b.end(),out)` | STL      | O(n+m) | O(n+m) |
| **Rust**       | Manual two pointers                              | ❌        | O(n+m) | O(n+m) |
| **Go**         | Manual                                           | ❌        | O(n+m) | O(n+m) |
| **Java**       | Manual                                           | ❌        | O(n+m) | O(n+m) |
| **Python**     | Manual                                           | ❌        | O(n+m) | O(n+m) |
| **JavaScript** | Manual                                           | ❌        | O(n+m) | O(n+m) |
| **C#**         | Manual                                           | ❌        | O(n+m) | O(n+m) |

### CP Recommendation

The two-pointer merge algorithm should be memorized—it appears frequently in contest problems.

# 2. Merge Sorted Lists

## Purpose

Merge two sorted linked lists.

Example

```text id="ndwjlwm"
List A

1 → 4 → 7

List B

2 → 3 → 8

↓

1 → 2 → 3 → 4 → 7 → 8
```

### Recommended Approach

```text id="3m9q4o"
Maintain one pointer
into each list.

Repeatedly attach
the smaller node.

Append the remaining list.
```

### Complexity

| Time   | Space          |
| ------ | -------------- |
| O(n+m) | O(1) iterative |

### CP Recommendation

Prefer the iterative solution over recursion to avoid stack overflow.

---

# 3. In-place Merge

## Purpose

Merge two consecutive sorted ranges within the same container.

Example

```text id="xq39ws"
Array

1 4 7 | 2 5 8

↓

1 2 4 5 7 8
```

| Language       | Built-in          | Notes                            |
| -------------- | ----------------- | -------------------------------- |
| **C++**        | `inplace_merge()` | ✅                                |
| **Rust**       | Manual            | Usually extra buffer             |
| **Go**         | Manual            | Complex without buffer           |
| **Java**       | Manual            | Complex                          |
| **Python**     | Manual            | Usually easier to use extra list |
| **JavaScript** | Manual            |                                  |
| **C#**         | Manual            |                                  |

### Complexity

| Time | Space         |
| ---- | ------------- |
| O(n) | Usually O(n)* |

* Truly in-place stable merging is considerably more complex and uncommon in Competitive Programming.

### CP Recommendation

Outside C++, using an auxiliary array is typically simpler and less error-prone.

# 4. K-way Merge

## Purpose

Merge **k** sorted arrays or lists.

Example

```text id="fq5nh9"
1 5 8

2 6

3 4 7

↓

1 2 3 4 5 6 7 8
```

### Standard Approach

Use a **Min Heap**.

Algorithm

```text id="j76jry"
Push first element
of every array

↓

Extract minimum

↓

Insert next element
from the same array
```

### Complexity

| Time       | Space |
| ---------- | ----- |
| O(N log k) | O(k)  |

where

```text id="8cy0jb"
N

=

total elements
```

### Language Support

| Language       | Recommended                         |
| -------------- | ----------------------------------- |
| **C++**        | `priority_queue`                    |
| **Rust**       | `BinaryHeap` (custom min-heap)      |
| **Go**         | `container/heap`                    |
| **Java**       | `PriorityQueue`                     |
| **Python**     | `heapq`                             |
| **JavaScript** | Manual heap / priority queue        |
| **C#**         | `PriorityQueue<TElement,TPriority>` |

### CP Recommendation

Always use a heap for K-way merge instead of repeatedly merging pairs.

---

# Merge vs Concatenate

| Feature       | Merge                 | Concatenate    |
| ------------- | --------------------- | -------------- |
| Inputs Sorted | ✅ Required            | ❌ Not required |
| Output Sorted | ✅                     | ❌              |
| Complexity    | O(n+m)                | O(n+m)         |
| CP Use        | Merge Sort, intervals | Appending data |

---

# Merge vs Sort

| Operation               | Complexity        |
| ----------------------- | ----------------- |
| Merge Two Sorted Arrays | O(n+m)            |
| Concatenate then Sort   | O((n+m) log(n+m)) |

### CP Recommendation

If both inputs are already sorted, **never concatenate and sort again**. Merging is asymptotically faster.

# CP Recommendations

* ✅ Memorize the **two-pointer merge** algorithm; it is one of the most common CP patterns.
* ✅ Use **merge** instead of sorting again when the inputs are already sorted.
* ✅ For linked lists, prefer the **iterative merge** to avoid recursion depth issues.
* ✅ Use a **Min Heap** for K-way merge; repeated pairwise merges are less efficient.
* ✅ In languages other than C++, using a temporary buffer for merging is usually simpler and acceptable.
* ✅ Recognize merge opportunities in interval problems, merge sort, and multi-source data processing.

---

# Common Mistakes

| Mistake                                           | Why It Happens                     | Better Approach                                     |
| ------------------------------------------------- | ---------------------------------- | --------------------------------------------------- |
| Concatenating and sorting already sorted arrays   | Unnecessary O((n+m) log(n+m)) work | Use two-pointer merge                               |
| Forgetting to append remaining elements           | One input finishes first           | Copy the remaining suffix                           |
| Using recursion for long linked lists             | Stack overflow risk                | Use iterative merge                                 |
| Attempting a complex in-place merge unnecessarily | Difficult to implement correctly   | Use an auxiliary array unless memory is constrained |
| Pairwise merging many arrays                      | Higher total complexity            | Use a Min Heap for K-way merge                      |

---

## Choosing the Right Merge Technique

| Scenario                           | Best Choice                                 |
| ---------------------------------- | ------------------------------------------- |
| Two sorted arrays                  | Two-pointer merge                           |
| Two sorted linked lists            | Iterative merge                             |
| Two sorted ranges in one container | `inplace_merge()` (C++) or auxiliary buffer |
| Many sorted arrays/lists           | Min Heap (K-way merge)                      |
| Inputs are unsorted                | Sort first, then merge if needed            |
| Merge Sort implementation          | Two-pointer merge                           |
