# Phase 1 — Common Competitive Programming Operations

# Topic 10 — Permutation Operations

Permutation operations are widely used in Competitive Programming for:

* Backtracking
* Brute-force search
* Lexicographical ordering
* Next/Previous configuration problems
* Traveling Salesman (small `n`)
* Combinatorial generation

A permutation is an arrangement of elements where order matters.

---

# 1. Generate All Permutations

## Purpose

Generate every possible ordering of a collection.

Example

```text
Input

1 2 3

↓

Permutations

123
132
213
231
312
321
```

### Recommended Approaches

| Language       | Idiomatic CP Syntax             | Built-in | Time      | Space |
| -------------- | ------------------------------- | -------- | --------- | ----- |
| **C++**        | `sort()` + `next_permutation()` | ✅        | O(n × n!) | O(1)* |
| **Rust**       | Backtracking                    | ❌        | O(n × n!) | O(n)  |
| **Go**         | Backtracking                    | ❌        | O(n × n!) | O(n)  |
| **Java**       | Backtracking                    | ❌        | O(n × n!) | O(n)  |
| **Python**     | `itertools.permutations()`      | ✅        | O(n × n!) | O(n)  |
| **JavaScript** | Backtracking                    | ❌        | O(n × n!) | O(n)  |
| **C#**         | Backtracking                    | ❌        | O(n × n!) | O(n)  |

* Excluding output storage.

### CP Recommendation

* **Small n (≤8~10):** Generate all permutations.
* **Larger n:** Look for mathematical or greedy solutions instead.

# 2. Next Permutation

## Purpose

Transform the current permutation into the next lexicographically larger permutation.

Example

```text
123

↓

132
```

```text
132

↓

213
```

If already the largest:

```text
321

↓

123
```

(reset to smallest)

---

### Built-in Support

| Language       | Idiomatic CP Syntax           | Built-in |
| -------------- | ----------------------------- | -------- |
| **C++**        | `next_permutation(begin,end)` | ✅        |
| **Rust**       | Manual                        | ❌        |
| **Go**         | Manual                        | ❌        |
| **Java**       | Manual                        | ❌        |
| **Python**     | Manual                        | ❌        |
| **JavaScript** | Manual                        | ❌        |
| **C#**         | Manual                        | ❌        |

### Algorithm

```text
1. Find first decreasing element from right.

2. Find next larger element.

3. Swap.

4. Reverse suffix.
```

### Complexity

* Time: **O(n)**
* Space: **O(1)**

### CP Recommendation

Memorize the algorithm. Only C++ provides a built-in implementation.

# 3. Previous Permutation

## Purpose

Generate the previous lexicographical permutation.

Example

```text
231

↓

213
```

### Built-in Support

| Language       | Idiomatic CP Syntax  |
| -------------- | -------------------- |
| **C++**        | `prev_permutation()` |
| **Rust**       | Manual               |
| **Go**         | Manual               |
| **Java**       | Manual               |
| **Python**     | Manual               |
| **JavaScript** | Manual               |
| **C#**         | Manual               |

### Algorithm

Mirror image of `next_permutation`:

```text
Find first increasing element
↓

Swap with previous smaller element
↓

Reverse suffix
```

### Complexity

* Time: **O(n)**
* Space: **O(1)**

# 4. Permutations with Duplicates

## Purpose

Generate only **unique** permutations when duplicate values exist.

Example

```text
Input

1 1 2

↓

112
121
211
```

(Not 6 permutations)

### Recommended Approaches

| Language       | Typical Method                                  |
| -------------- | ----------------------------------------------- |
| **C++**        | Sort + `next_permutation()`                     |
| **Rust**       | Sort + Backtracking + Skip duplicates           |
| **Go**         | Same                                            |
| **Java**       | Same                                            |
| **Python**     | Sort + Backtracking (or `set` for small inputs) |
| **JavaScript** | Same                                            |
| **C#**         | Same                                            |

### Duplicate-Skipping Rule

After sorting:

```text
Skip element i when

nums[i] == nums[i-1]

AND

nums[i-1] has not been used
```

This avoids generating duplicate permutations.

### Complexity

Worst case:

```text
O(n × n!)
```

Fewer unique permutations are generated when duplicates exist.

### CP Recommendation

Sorting before backtracking simplifies duplicate handling.

# CP Recommendations

* ✅ Use `next_permutation()` in C++ whenever possible—it is concise and highly optimized.
* ✅ In Python, use `itertools.permutations()` for straightforward permutation generation.
* ✅ For languages without built-in support, implement a standard backtracking template once and reuse it.
* ✅ Always **sort** the input before generating unique permutations.
* ✅ Avoid generating all permutations unless `n` is small (typically `n ≤ 8–10`).
* ✅ Learn the **Next Permutation** algorithm; it is a common interview and contest topic even in languages without a built-in API.

---

# Common Mistakes

| Mistake                                                  | Why It Happens                            | Better Approach                                |
| -------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------- |
| Generating permutations for large `n`                    | Factorial growth (`n!`)                   | Look for greedy, DP, or mathematical solutions |
| Forgetting to sort before `next_permutation()`           | Lexicographic sequence starts incorrectly | Sort first                                     |
| Producing duplicate permutations                         | Duplicate values not handled              | Sort and skip duplicates during backtracking   |
| Using a `set` to remove duplicates for large inputs      | High memory and runtime overhead          | Skip duplicates during generation              |
| Forgetting to reverse the suffix in `next_permutation()` | Incorrect next permutation                | Follow the standard 4-step algorithm           |

---

## Choosing the Right Permutation Technique

| Scenario                                    | Best Choice                                                      |
| ------------------------------------------- | ---------------------------------------------------------------- |
| Generate all permutations                   | Backtracking / `itertools.permutations()` / `next_permutation()` |
| Generate next lexicographic arrangement     | `next_permutation()` or manual algorithm                         |
| Generate previous lexicographic arrangement | `prev_permutation()` or manual algorithm                         |
| Handle duplicate elements                   | Sort + duplicate-skipping backtracking                           |
| Enumerate permutations in order             | Start sorted and repeatedly apply `next_permutation()`           |

---

### Note

Although C++ has excellent built-in permutation support, **every competitive programmer should understand the manual `next_permutation` algorithm**, since it is frequently required in languages without a standard implementation and occasionally appears as a standalone interview or contest problem.
