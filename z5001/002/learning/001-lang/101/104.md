# Phase 1 — Common Competitive Programming Operations

# Topic 4 — Binary Search Operations

Binary Search is one of the most important techniques in Competitive Programming. Besides searching for an element, it is used for:

* Finding insertion positions
* Finding first/last occurrence
* Counting occurrences
* Maintaining sorted containers
* Binary Search on Answer
* Optimization problems

Most languages provide efficient library support, though the APIs differ.

---

# 1. Binary Search

## Purpose

Determine whether a value exists in a **sorted** collection.

Example

```text
Array: 1 3 5 7 9

Search 5 → Found
Search 6 → Not Found
```

| Language       | Idiomatic CP Syntax                    | Built-in | Return                           | Time     | Space |
| -------------- | -------------------------------------- | -------- | -------------------------------- | -------- | ----- |
| **C++**        | `binary_search(v.begin(), v.end(), x)` | STL      | `bool`                           | O(log n) | O(1)  |
| **Rust**       | `v.binary_search(&x)`                  | std      | `Result<usize, usize>`           | O(log n) | O(1)  |
| **Go**         | `slices.BinarySearch(arr, x)`          | `slices` | `(idx, found)`                   | O(log n) | O(1)  |
| **Java**       | `Arrays.binarySearch(arr, x)`          | JDK      | index / negative insertion point | O(log n) | O(1)  |
| **Python**     | `bisect_left()` + compare              | `bisect` | manual                           | O(log n) | O(1)  |
| **JavaScript** | Manual                                 | ❌        | manual                           | O(log n) | O(1)  |
| **C#**         | `Array.BinarySearch(arr, x)`           | .NET     | index / negative insertion point | O(log n) | O(1)  |

### CP Recommendation

* Always ensure the collection is **sorted** before binary searching.
* In Python, use the `bisect` module instead of implementing binary search manually unless required.

# 2. lower_bound

## Purpose

Find the **first element ≥ x**.

Example

```text
Array

1 2 2 2 4 6

x = 2

Result index = 1
```

| Language       | Idiomatic CP Syntax                                              |    |                                     |
| -------------- | ---------------------------------------------------------------- | -- | ----------------------------------- |
| **C++**        | `lower_bound(begin, end, x)`                                     |    |                                     |
| **Rust**       | `partition_point(                                                | &v | v < x)`*(or`binary_search` result)* |
| **Go**         | `sort.Search(len(arr), func(i int) bool { return arr[i] >= x })` |    |                                     |
| **Java**       | Use `Arrays.binarySearch()` + adjust, or manual                  |    |                                     |
| **Python**     | `bisect_left(arr, x)`                                            |    |                                     |
| **JavaScript** | Manual                                                           |    |                                     |
| **C#**         | Manual / adjust `BinarySearch()` result                          |    |                                     |

### Returns

```text
First position where x can be inserted
without breaking sorted order.
```

# 4. equal_range

## Purpose

Find both `lower_bound` and `upper_bound` in one operation.

Useful for:

* Counting duplicates
* Range queries

Example

```text
1 2 2 2 4

equal_range(2)

↓

[1,4)
```

| Language       | Built-in          | Notes                              |
| -------------- | ----------------- | ---------------------------------- |
| **C++**        | ✅ `equal_range()` | Returns pair of iterators          |
| **Rust**       | ❌                 | Use two `partition_point()` calls  |
| **Go**         | ❌                 | Two `Search()` calls               |
| **Java**       | ❌                 | Two searches                       |
| **Python**     | ❌                 | `bisect_left()` + `bisect_right()` |
| **JavaScript** | ❌                 | Manual                             |
| **C#**         | ❌                 | Manual                             |

### Complexity

* O(log n)

# 5. First Occurrence

## Purpose

Find the first index containing `x`.

Example

```text
1 2 2 2 3

x = 2

Answer = 1
```

### Recommended Approach

| Language   | Method               |
| ---------- | -------------------- |
| C++        | `lower_bound()`      |
| Rust       | `partition_point()`  |
| Go         | `Search()`           |
| Java       | Manual binary search |
| Python     | `bisect_left()`      |
| JavaScript | Manual binary search |
| C#         | Manual binary search |

### Check

```text
idx < n && arr[idx] == x
```

Otherwise, the element does not exist.

# 7. Insertion Position

## Purpose

Determine where a value should be inserted while keeping the array sorted.

Example

```text
1 3 5 7

Insert 4

↓

Position = 2
```

| Language   | Method                                |
| ---------- | ------------------------------------- |
| C++        | `lower_bound()`                       |
| Rust       | `binary_search()` (`Err(idx)`)        |
| Go         | `Search()`                            |
| Java       | Negative result from `binarySearch()` |
| Python     | `bisect_left()`                       |
| JavaScript | Manual                                |
| C#         | Negative result from `BinarySearch()` |

### Java / C#

If `idx < 0`:

```text
Insertion Point = -(idx + 1)
```

# 8. Bisect Equivalents

## Purpose

Map Python's `bisect` operations to equivalent APIs in other languages.

| Python         | Meaning   | C++           | Rust                  | Go           | Java   | JS     | C#     |
| -------------- | --------- | ------------- | --------------------- | ------------ | ------ | ------ | ------ |
| `bisect_left`  | first ≥ x | `lower_bound` | `partition_point(<)`  | `Search(>=)` | Manual | Manual | Manual |
| `bisect_right` | first > x | `upper_bound` | `partition_point(<=)` | `Search(>)`  | Manual | Manual | Manual |

### CP Recommendation

Learn `bisect_left` and `bisect_right`; they correspond directly to `lower_bound` and `upper_bound`.

# 9. Binary Search on Answer

## Purpose

Binary search over the **answer space** instead of the array.

Common in optimization problems where you need the minimum or maximum feasible value.

Typical pattern:

```text
low = minimum possible answer
high = maximum possible answer

while low <= high
    mid = (low + high) / 2

    if feasible(mid)
        answer = mid
        move toward better answer
    else
        move toward feasible region
```

### Typical Problems

* Minimum capacity
* Maximum minimum distance
* Minimum speed
* Allocate books
* Aggressive cows
* Koko Eating Bananas
* Ship Packages Within D Days

### Complexity

```text
O(log AnswerRange × FeasibilityCheck)
```

### CP Recommendation

* The feasibility function should be **monotonic**.
* Avoid floating-point binary search unless necessary.

# CP Recommendations

* ✅ Ensure the input is sorted before using binary search APIs.
* ✅ Prefer `lower_bound`/`upper_bound` (or their equivalents) over writing custom binary searches.
* ✅ Compute the midpoint safely to avoid overflow:

  * `mid = low + (high - low) / 2`
* ✅ For duplicate values, use `lower_bound` for the first occurrence and `upper_bound - 1` for the last occurrence.
* ✅ Use Binary Search on Answer only when the feasibility condition is monotonic.
* ✅ In Python, favor the `bisect` module over manual implementations.

# Common Mistakes

| Mistake                                                       | Why It Happens                            | Better Approach                                |
| ------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------- |
| Binary searching an unsorted array                            | Preconditions ignored                     | Sort first or use a different algorithm        |
| Using `(low + high) / 2` on large integers                    | Possible overflow in some languages       | `low + (high - low) / 2`                       |
| Forgetting to verify `arr[idx] == x` after `lower_bound`      | `lower_bound` returns insertion position  | Validate the index before using it             |
| Misinterpreting negative return values in Java/C#             | `binarySearch()` encodes insertion points | Recover with `-(idx + 1)`                      |
| Applying Binary Search on Answer to a non-monotonic predicate | Incorrect problem modeling                | Verify monotonicity before using the technique |
