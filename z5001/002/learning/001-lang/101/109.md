# Phase 1 — Common Competitive Programming Operations

# Topic 9 — GCD / LCM Operations

Greatest Common Divisor (GCD) and Least Common Multiple (LCM) are fundamental mathematical operations in Competitive Programming. They appear frequently in:

* Number Theory
* Fractions
* Modular Arithmetic
* Diophantine Equations
* Prime Factorization
* Geometry
* Graph Problems
* Inclusion-Exclusion

The **Euclidean Algorithm** computes GCD efficiently in **O(log(min(a, b)))** time.

---

# 1. `gcd`

## Purpose

Compute the **Greatest Common Divisor** of two integers.

Example

```text id="go2zfx"
gcd(24, 18)

↓

6
```

### Euclidean Algorithm

```text id="dw8eq6"
while b ≠ 0
    a, b = b, a % b

return a
```

| Language       | Idiomatic CP Syntax           | Built-in | Time     | Space |
| -------------- | ----------------------------- | -------- | -------- | ----- |
| **C++**        | `gcd(a, b)` *(<numeric>)*     | ✅        | O(log n) | O(1)  |
| **Rust**       | Manual / `num::integer::gcd`* | Partial  | O(log n) | O(1)  |
| **Go**         | Manual                        | ❌        | O(log n) | O(1)  |
| **Java**       | Manual                        | ❌        | O(log n) | O(1)  |
| **Python**     | `math.gcd(a, b)`              | ✅        | O(log n) | O(1)  |
| **JavaScript** | Manual                        | ❌        | O(log n) | O(1)  |
| **C#**         | Manual                        | ❌        | O(log n) | O(1)  |

* External crates such as `num` are generally unavailable in many contest environments. Implement Euclid manually.

### CP Recommendation

* In Rust, Go, Java, JavaScript, and C#, keep a short Euclidean GCD helper in your template.
* Handle negative values by taking the absolute value if required by the problem.

# 2. `lcm`

## Purpose

Compute the **Least Common Multiple**.

Formula

```text id="xt13dm"
lcm(a, b)

=

(a / gcd(a, b)) × b
```

Example

```text id="wkcpry"
lcm(12, 18)

↓

36
```

### Why divide first?

```text id="zjlwmv"
(a × b) / gcd

may overflow

↓

(a / gcd) × b

is safer
```

| Language       | Built-in                 | Recommended          |
| -------------- | ------------------------ | -------------------- |
| **C++**        | `lcm(a,b)` *(C++17)*     | ✅                    |
| **Rust**       | Manual                   | `(a / gcd(a,b)) * b` |
| **Go**         | Manual                   | Same                 |
| **Java**       | Manual                   | Same                 |
| **Python**     | `math.lcm(a,b)` *(3.9+)* | ✅                    |
| **JavaScript** | Manual                   | Same                 |
| **C#**         | Manual                   | Same                 |

### Complexity

* **Time:** O(log n) (dominated by GCD)
* **Space:** O(1)

### CP Recommendation

Always compute `a / gcd(a, b)` before multiplying to reduce overflow risk.

# 3. Extended GCD

## Purpose

Compute integers `x` and `y` such that:

```text id="g8v0ul"
ax + by = gcd(a, b)
```

It returns:

* `g = gcd(a, b)`
* Coefficients `x`
* Coefficients `y`

Example

```text id="ckr8n8"
a = 30

b = 18

↓

gcd = 6

One solution

x = -1

y = 2

30(-1) + 18(2) = 6
```

### Recursive Algorithm

```text id="5xjlwm"
if b == 0

    return (a, 1, 0)

(g, x1, y1) = extgcd(b, a % b)

x = y1

y = x1 - (a / b) * y1
```

### Complexity

| Time     | Space              |
| -------- | ------------------ |
| O(log n) | O(log n) recursive |

### Typical Uses

* Modular Inverse
* Chinese Remainder Theorem
* Linear Diophantine Equations
* Bézout's Identity

# CP Recommendations

* ✅ Memorize the Euclidean Algorithm; it should be part of every CP template.
* ✅ Use built-in `gcd`/`lcm` where available (C++, Python).
* ✅ Compute LCM as `(a / gcd(a, b)) * b` to minimize overflow risk.
* ✅ Include an **Extended GCD** helper in your template if you solve number theory problems.
* ✅ Use iterative GCD when possible for slightly lower overhead than recursion.
* ✅ Normalize inputs (e.g., use absolute values) if the problem allows negative numbers.

---

# Common Mistakes

| Mistake                                                     | Why It Happens                           | Better Approach                           |                   |                        |
| ----------------------------------------------------------- | ---------------------------------------- | ----------------------------------------- | ----------------- | ---------------------- |
| Computing `a * b / gcd`                                     | Multiplication may overflow              | Compute `(a / gcd) * b`                   |                   |                        |
| Assuming GCD is always positive                             | Negative inputs                          | Normalize with absolute values            |                   |                        |
| Forgetting `gcd(a, 0) =                                     | a                                        | `                                         | Missing base case | Handle zero explicitly |
| Using recursion without a correct base case in Extended GCD | Infinite recursion or wrong coefficients | Follow the standard recursive formulation |                   |                        |
| Relying on external libraries in contests                   | Often unavailable                        | Keep manual GCD/Extended GCD helpers      |                   |                        |

---

## Choosing the Right Operation

| Scenario                                  | Best Choice  |
| ----------------------------------------- | ------------ |
| Find common divisor                       | GCD          |
| Find common multiple                      | LCM          |
| Reduce a fraction                         | GCD          |
| Compute modular inverse (when applicable) | Extended GCD |
| Solve `ax + by = c`                       | Extended GCD |
| Chinese Remainder Theorem                 | Extended GCD |
