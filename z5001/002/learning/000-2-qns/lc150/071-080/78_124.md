# Binary Tree Maximum Path Sum

## Difficulty
Hard

## Description
Given a non-empty binary tree, find the maximum path sum. A path is any sequence of nodes from some starting node to any node in the tree along the parent-child connections. The path must contain at least one node and does not need to go through the root.

## Examples

### Example 1

```text
Input: [-10,9,20,null,null,15,7]
Output: 42
Explanation: The optimal path is 15 -> 20 -> 7 giving sum 42.
```

### Example 2

```text
Input: [2, -1]
Output: 2
Explanation: The optimal path is node 2 alone.
```

### Example 3

```text
Input: [-3]
Output: -3
Explanation: Single node negative value is the path.
```

## Constraints

```text
The number of nodes is in the range [1, 3 * 10^4].
-10^4 <= Node.val <= 10^4
Tree is a binary tree; input often given as array with nulls for missing children.
```

---

## Idea
Use post-order DFS to compute the maximum downward path (gain) from each node and update global max with node.val + leftGain + rightGain.

---

## Pseudo Code

```text
function maxPathSum(root)
    maxSum <- -infinity
    function maxGain(node)
        if node is null then return 0
        leftGain <- max(0, maxGain(node.left))
        rightGain <- max(0, maxGain(node.right))
        priceNewPath <- node.val + leftGain + rightGain
        maxSum <- max(maxSum, priceNewPath)
        return node.val + max(leftGain, rightGain)
    maxGain(root)
    return maxSum
```

---

## Complexity

| Metric           | Value  |
| ---------------- | ------ |
| Time Complexity  | O(n)   |
| Space Complexity | O(h) (recursion stack), h = tree height |

---

## Code Explanation

### Dry Run

| Step | State (node) | Operation | Result |
| ---- | ------------ | --------- | ------ |
| 1    | 9 (left of -10) | maxGain(9): left=0,right=0,price=9 | return 9, maxSum=9 |
| 2    | 15 (left of 20) | maxGain(15): left=0,right=0,price=15 | return 15, maxSum=15 |
| 3    | 7 (right of 20) | maxGain(7): left=0,right=0,price=7 | return 7, maxSum=15 |
| 4    | 20 | leftGain=15,rightGain=7,price=42 | return 20+max(15,7)=35, maxSum=42 |
| 5    | -10 (root) | leftGain=9,rightGain=35,price=34 | return -10+max(9,35)=25, maxSum=42 |

1. Compute gains bottom-up.
2. At each node update maxSum with node.val + leftGain + rightGain.
3. Return node.val plus larger child gain for parent use.
4. Final maxSum is the answer.

## Other Patterns

### Pattern 1

**Idea**

Iterative post-order traversal with explicit stack and visited flag to compute gains bottom-up.

**Pseudo Code**

```text
function maxPathSumIterative(root)
    if root is null then return 0
    stack <- [(root, false)]
    gains <- map node -> 0
    maxSum <- -infinity
    while stack not empty
        node, visited <- pop(stack)
        if node is null then continue
        if visited is false
            push(stack, (node, true))
            push(stack, (node.right, false))
            push(stack, (node.left, false))
        else
            leftGain <- max(0, gains.get(node.left, 0))
            rightGain <- max(0, gains.get(node.right, 0))
            priceNewPath <- node.val + leftGain + rightGain
            maxSum <- max(maxSum, priceNewPath)
            gains[node] <- node.val + max(leftGain, rightGain)
    return maxSum
```

### Pattern 2

**Idea**

Tree DP with two passes: first compute max downward for all nodes, second compute combining upward contributions (rerooting technique).

**Pseudo Code**

```text
function maxPathSumReroot(root)
    compute down[node] = max(node.val, node.val + max(down[left], down[right]))
    use reroot recursion to compute best combining parent contribution and update global max
    return global max
```

## Comparison

| Approach | Idea | Time | Space | Recommended |
| -------- | ---- | ---- | ----- | ----------- |
| DFS recursion (main) | Post-order compute max downward gain and update global max | O(n) | O(h) | Yes |
| Iterative post-order | Explicit stack with visited flag to simulate post-order | O(n) | O(n) (stack + map) | No (useful when recursion not allowed) |
| Rerooting DP | Two-pass DP computing downward and rerooted contributions | O(n) | O(n) | No (more complex) |
