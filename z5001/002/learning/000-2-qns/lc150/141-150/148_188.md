# Best Time to Buy and Sell Stock IV

## Difficulty
Hard

## Description
Given k and an array prices where prices[i] is the stock price on day i, compute the maximum profit with at most k transactions (a transaction = one buy + one sell). You may not engage in multiple transactions simultaneously (must sell before buy).

## Examples

### Example 1

```text
Input: k = 2, prices = [2,4,1]
Output: 2
Explanation: Buy on day0 (price=2) and sell on day1 (price=4) => profit 2.
```

### Example 2

```text
Input: k = 2, prices = [3,2,6,5,0,3]
Output: 7
Explanation: Buy day1 (2) sell day2 (6) profit 4, buy day4 (0) sell day5 (3) profit 3 => total 7.
```

## Constraints

```text
0 <= k
0 <= prices.length <= 10^5
0 <= prices[i] <= 10^5
```

---

## Idea
Use DP optimizing across transactions: if k >= n/2 reduce to unlimited-transaction greedy; else maintain buy[t], sell[t] for t=1..k and update per price.

---

## Pseudo Code

```text
function solve(k, prices)
    n = length(prices)
    if n == 0 or k == 0
        return 0
    if k >= n / 2
        return sum(max(0, prices[i] - prices[i-1]) for i from 1 to n-1)
    create array buy[0..k] and sell[0..k]
    for t from 0 to k
        buy[t] = -infinity
        sell[t] = 0
    for each price in prices
        for t from 1 to k
            buy[t] = max(buy[t], sell[t-1] - price)
            sell[t] = max(sell[t], buy[t] + price)
    return sell[k]
```

---

## Complexity

| Metric           | Value  |
| ---------------- | ------ |
| Time Complexity  | O(min(k, n) * n) |
| Space Complexity | O(k)  |

---

## Code Explanation

### Dry Run

| Step | price | buy[1] | sell[1] | buy[2] | sell[2] |
| ---- | ----- | ------ | ------- | ------ | ------- |
| init | -     | -inf   | 0       | -inf   | 0       |
| 1    | 2     | max(-inf, 0-2) = -2 | max(0, -inf+2)=0 | max(-inf, 0-2)=-2 | 0 |
| 2    | 4     | max(-2, 0-4) = -2   | max(0, -2+4)=2  | max(-2, 0-4)=-2  | max(0, -2+4)=2 |
| 3    | 1     | max(-2, 0-1) = -1   | max(2, -1+1)=2  | max(-2, 2-1)=1   | max(2, 1+1)=2  |
| end  | -     | -1    | 2       | 1      | 2       |

Result = sell[2] = 2

1. If k >= n/2 treat as unlimited transactions: sum of positive day differences.
2. Otherwise maintain best "buy" and "sell" for each transaction count and update per price.
3. buy[t] represents max balance after a buy for transaction t.
4. sell[t] represents max profit after completing up to t transactions.
5. Final answer is sell[k].

## Other Patterns

### Pattern 1

**Idea**

Greedy: when k large (>= n/2), take all positive gains.

**Pseudo Code**

```text
function solve_greedy(k, prices)
    n = length(prices)
    if n <= 1
        return 0
    profit = 0
    for i from 1 to n-1
        if prices[i] > prices[i-1]
            profit = profit + prices[i] - prices[i-1]
    return profit
```

### Pattern 2

**Idea**

Full DP table dp[i][t][holding] with i days, t transactions used, holding in {0,1}.

**Pseudo Code**

```text
function solve_full_dp(k, prices)
    n = length(prices)
    if n == 0
        return 0
    create dp[0..n-1][0..k][0..1] initialized to -infinity or 0 appropriately
    set dp[0][0][0] = 0
    set dp[0][1][1] = -prices[0]
    ... (fill transitions)
    return max(dp[n-1][t][0] for t from 0 to k)
```

## Comparison

| Approach    | Idea                                 | Time           | Space | Recommended |
| ----------- | ------------------------------------ | -------------- | ----- | ----------- |
| Optimized DP| maintain buy[t], sell[t] per price   | O(k * n)       | O(k)  | Yes         |
| Greedy      | sum positive diffs when k >= n/2     | O(n)           | O(1)  | Yes (special case) |
| Full DP     | 3D DP table over days, transactions  | O(k * n)       | O(k * n) | No        |
