## 039. Path Sum III

**Difficulty:** Medium

### Description

Given the `root` of a binary tree and an integer `targetSum`, return the number of paths where the sum of the values along the path equals `targetSum`.

The path does **not** need to start at the root or end at a leaf, but it must go **downwards** (from parent to child).

---

### Examples

```text
Input:
root=[10,5,-3,3,2,null,11,3,-2,null,1]
targetSum=8

Output:
3

Explanation:

        10
       /  \
      5   -3
     / \    \
    3   2    11
   / \   \
  3  -2   1

Paths having sum=8:

5->3
5->2->1
-3->11

Total paths=3
```

```text
Input:
root=[5,4,8,11,null,13,4,7,2,null,null,5,1]
targetSum=22

Output:
3
```

---

### Constraints

```text
Number of nodes is in the range [0,1000].
-10^9<=Node.val<=10^9
-1000<=targetSum<=1000
```

---

## Idea (One Line)

Use Prefix Sum with DFS to count how many previous prefix sums equal `currentSum-targetSum`.
```
# 1
prefixCount[currentSum - targetSum]
        ↓
Number of NEW paths discovered
that END at the current node.

# 2
paths(currentNode) =
    paths(left subtree)
  + new paths ending at current node        
  + paths(right subtree)

ie 
Total paths returned by this node =
    paths in left subtree
  + paths ending at this node
  + paths in right subtree
```

---

## Pseudocode (Prefix Sum + DFS)

```text
function pathSum(root,targetSum)
    prefixCount=emptyMap()
    prefixCount[0]=1
    return dfs(root,0,targetSum,prefixCount)

function dfs(node,currentSum,targetSum,prefixCount)
    if node==null
        return 0
    currentSum=currentSum+node.val
    count=0
    if currentSum-targetSum in prefixCount
        count=prefixCount[currentSum-targetSum]
    if currentSum not in prefixCount
        prefixCount[currentSum]=0
    prefixCount[currentSum]=prefixCount[currentSum]+1
    count=count+dfs(node.left,currentSum,targetSum,prefixCount)
    count=count+dfs(node.right,currentSum,targetSum,prefixCount)
    prefixCount[currentSum]=prefixCount[currentSum]-1
    return count
```

## Complexity

```text
Time Complexity: O(n)
Space Complexity: O(n)

n=number of nodes
```

## Code Explanation

```text
1. Maintain prefix sums from root to current node.
2. currentSum stores sum from root to current node.
3. To find targetSum ending at current node, check currentSum-targetSum.
4. If found in map, add its frequency to answer.
5. Store currentSum in map before exploring children.
6. Recursively process left subtree.
7. Recursively process right subtree.
8. Remove currentSum while backtracking.
9. Return total count.
```

---

# Why Prefix Sum Works

Suppose

```text
prefixSum(j)-prefixSum(i)=targetSum
```

Then

```text
prefixSum(i)=prefixSum(j)-targetSum
```

So at every node:

```text
Required previous prefix=currentSum-targetSum
```

If it exists in the map, we found one or more valid paths.

# Other Patterns

## 1. Brute Force DFS From Every Node

### Idea

Start DFS from every node and count paths having target sum.

```
Simple Algorithm (Brute Force DFS)
    For every node:
        Assume this node is the starting node.
        Count all downward paths starting from this node whose sum equals target.
        Repeat for every node in the tree.

    So you perform two DFS traversals:
        DFS 1: Visit every node.
        DFS 2: From that node, count all valid downward paths.
```
### Pseudocode

```text
function pathSum(root,targetSum)
    if root==null
        return 0

    return countFrom(root,targetSum)+pathSum(root.left,targetSum)+pathSum(root.right,targetSum)


function countFrom(node,target)
    if node==null
        return 0

    count=0

    if node.val==target
        count=1

    count=count+countFrom(node.left,target-node.val)
    count=count+countFrom(node.right,target-node.val)

    return count
```

Time Complexity

Suppose there are N nodes.

For each node, you may traverse its subtree.
```
N × N = O(N²)
```

For a balanced tree, it's closer to O(N log N) on average, but the worst case (a skewed tree) is O(N²).

## 2. DFS Using Path Array

### Idea

Store root-to-node path and check all suffix sums.

### Pseudocode

```text
function pathSum(root,targetSum)
    path=emptyList()

    return dfs(root,targetSum,path)


function dfs(node,targetSum,path)
    if node==null
        return 0

    append node.val into path

    sum=0
    count=0

    for i=length(path)-1 down to 0
        sum=sum+path[i]

        if sum==targetSum
            count=count+1

    count=count+dfs(node.left,targetSum,path)
    count=count+dfs(node.right,targetSum,path)

    remove last element from path

    return count
```

## 3. Iterative DFS With Prefix Map

### Idea

Use stack with prefix sums instead of recursion.

### Pseudocode

```text
function pathSum(root,targetSum)
    stack=emptyStack()

    push(root,0)

    perform DFS using stack and prefix map

    return answer
```

```
function pathSum(root, targetSum)
    if root == null
        return 0
    prefixCount = {}
    prefixCount[0] = 1
    answer = 0
    stack = empty
    stack.push((root, 0, false))
        // node, parentSum, exiting?
    while stack is not empty
        node, parentSum, exiting = pop(stack)
        if node == null
            continue
        if exiting == false
            currentSum = parentSum + node.val
            answer += prefixCount.get(currentSum - targetSum, 0)
            prefixCount[currentSum] =
                prefixCount.get(currentSum,0) + 1
            // Exit frame (backtracking)
            stack.push((node, currentSum, true))
            // Children
            stack.push((node.right, currentSum, false))
            stack.push((node.left, currentSum, false))
        else
            // Backtracking
            prefixCount[parentSum]--
    return answer
```

# Comparison of Approaches

| Approach             | Idea                      |  Time | Space | Recommended |
| -------------------- | ------------------------- | ----: | ----: | ----------: |
| Prefix Sum+DFS       | HashMap of prefix sums    |  O(n) |  O(n) |       ⭐⭐⭐⭐⭐ |
| Brute Force DFS      | Start DFS from every node | O(n²) |  O(h) |         ⭐⭐⭐ |
| DFS With Path Array  | Check suffix sums         | O(nh) |  O(h) |         ⭐⭐⭐ |
| Iterative Prefix Sum | Stack+HashMap             |  O(n) |  O(n) |        ⭐⭐⭐⭐ |

where

```text
n=number of nodes
h=height of tree

Balanced tree: h=logn
Worst case: h=n
```

## Best Choice

```text
Interview: Prefix Sum+DFS

Reason:
1. O(n) time complexity.
2. Uses HashMap for constant time lookup.
3. Avoids repeated traversal from every node.
4. Elegant extension of Prefix Sum technique used in arrays.
5. Standard optimal solution for LC 437.
```

### ⭐ This is the example that proves **why we store counts instead of a set**

At **Step 3**:

```text
Map Before

{0:3}
```

means there are **three different prefixes** with sum `0`.

So

```text
currentSum = 0
target = 0

need = 0
```

The algorithm does

```text
count += prefixCount[0]
```

which is

```text
count += 3
```

So **three different paths end at this node**.

If you had used a **set**:

```text
{0}
```

you would only know that `0` exists, and you would incorrectly count **1 path** instead of **3**. This example is the clearest demonstration of why `prefixCount` stores **frequencies**, not just existence.

## Why "Found = 3"?

Take the leftmost leaf:

```
        0
      /
     0
    /
   0
```

Before visiting this leaf:

```
Map = {0:3}
```

Those three occurrences of prefix sum `0` correspond to:

```
Before root        prefix = 0
After root         prefix = 0
After left child   prefix = 0
```

So there are **three different places** where a valid path can start.

```
Start before root
|
v
0 → 0 → 0

Start at root
    |
    v
    0 → 0

Start at left child
        |
        v
        0
```

All three paths end at the current leaf and all sum to `0`.

That's why:

```
prefixCount[0] = 3

count += 3
```

---

This example is the one that usually makes the prefix-sum map "click": **the map doesn't remember nodes; it remembers how many different starting positions (prefixes) exist on the current root-to-node path.** Each occurrence of the same prefix sum represents another possible starting point for a valid path ending at the current node.
