# Successful Pairs of Spells and Potions

## Difficulty
Medium

## Description
Given arrays spells and potions and an integer success, for each spell count how many potions form a successful pair with that spell. A pair (spell, potion) is successful if spell * potion >= success.

## Examples

### Example 1

```text
Input: spells = [5,1,3], potions = [1,2,3,4,5], success = 7
Output: [4,0,3]
Explanation: For spell 5 valid potions are [2,3,4,5] => 4.
             For spell 1 none => 0.
             For spell 3 valid potions are [3,4,5] => 3.
```

## Constraints

```text
1 <= spells.length, potions.length <= 10^5
1 <= spells[i], potions[i] <= 10^5
1 <= success <= 10^10
```

---

## Idea
Sort potions and for each spell use binary search to find the first potion >= ceil(success / spell), then count suffix length.

---

## Pseudo Code

```text
function successfulPairs(spells, potions, success)
    sort(potions)                                  // ascending
    n <- length(potions)
    result <- array of zeros with length(spells)
    for i from 0 to length(spells)-1
        spell <- spells[i]
        if spell == 0
            result[i] <- 0
            continue
        need <- ceil_div(success, spell)          // minimal potion value required
        idx <- lower_bound(potions, need)         // first index with potions[idx] >= need
        if idx == n
            result[i] <- 0
        else
            result[i] <- n - idx
    return result

function lower_bound(arr, target)
    lo <- 0
    hi <- length(arr)                             // exclusive
    while lo < hi
        mid <- lo + (hi - lo) // 2
        if arr[mid] < target
            lo <- mid + 1
        else
            hi <- mid
    return lo

function ceil_div(a, b)                           // a, b positive integers
    return (a + b - 1) // b
```

---

## Complexity

| Metric           | Value                           |
| ---------------- | ------------------------------- |
| Time Complexity  | O(P log P + S log P)            |
| Space Complexity | O(1) extra (excluding output)   |

P = number of potions, S = number of spells.

---

## Code Explanation

### Dry Run

| Step | State                                 | Operation                                  | Result                 |
| ---- | ------------------------------------- | ------------------------------------------ | ---------------------- |
| 1    | potions = [1,2,3,4,5], spells index 0 | sort potions                               | [1,2,3,4,5]            |
| 2    | spell = 5                             | need = ceil(7/5) = 2                       | need = 2               |
| 3    | lower_bound([1,2,3,4,5], 2)           | returns index 1                             | count = 5-1 = 4        |
| 4    | spell = 1                             | need = ceil(7/1) = 7                       | lower_bound -> index 5 |
| 5    | index == n                            | count = 0                                  | result[1] = 0          |
| 6    | spell = 3                             | need = ceil(7/3) = 3                       | lower_bound -> index 2 |
| 7    | compute count                         | count = 5-2 = 3                            | result[2] = 3          |

1. Sort potions once.
2. For each spell compute minimal required potion via ceil_div.
3. Binary search the first potion >= required.
4. Suffix length is the count of successful potions.

## Other Patterns

### Pattern 1

**Idea**

Sort both arrays and use two pointers from largest to smallest to compute counts in one pass.

**Pseudo Code**

```text
function successfulPairs_twoPointers(spells, potions, success)
    indexed_spells <- list of (spell, original_index) for each spell
    sort(indexed_spells) descending by spell
    sort(potions) ascending
    n <- length(potions)
    res <- array of zeros with length(indexed_spells)
    j <- n - 1
    for each (spell, idx) in indexed_spells
        while j >= 0 and spell * potions[j] >= success
            j <- j - 1
        res[idx] <- n - (j + 1)
    return res
```

### Pattern 2

**Idea**

Use counting sort/frequency on potion values if range is small, compute suffix sums to answer in O(1) per spell.

**Pseudo Code**

```text
function successfulPairs_counting(spells, potions, success, MAXV)
    freq <- array of zeros size MAXV+1
    for p in potions
        freq[p] <- freq[p] + 1
    suffix <- array of zeros size MAXV+2
    for v from MAXV down to 1
        suffix[v] <- suffix[v+1] + freq[v]
    res <- array of zeros length(spells)
    for i from 0 to length(spells)-1
        need <- ceil_div(success, spells[i])
        if need > MAXV
            res[i] <- 0
        else
            res[i] <- suffix[max(1, need)]
    return res
```

## Comparison

| Approach             | Idea                                      | Time                          | Space                   | Recommended |
| -------------------- | ----------------------------------------- | ----------------------------- | ----------------------- | ----------- |
| Sorting + BinarySearch | Sort potions and binary search per spell | O(P log P + S log P)          | O(1) extra              | Yes         |
| Two Pointers         | Sort spells desc and potions asc, sweep   | O(P log P + S log S + P + S)  | O(1) extra              | No (useful when sorting both is fine) |
| Counting + Suffix    | Build freq and suffix sums                | O(P + MAXV + S)               | O(MAXV)                | No (only if MAXV small)
