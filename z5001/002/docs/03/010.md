# LRU Cache

Design a cache that supports:

* `get(key)` → return value if present, else `-1`
* `put(key, value)` → insert/update key
* When capacity exceeds, remove **Least Recently Used (LRU)** item

Used in:

* Amazon
* Google
* Meta
* Microsoft
* Apple

Difficulty: Medium

---

# Main Solution Patterns

| Pattern            | Data Structures              | Get  | Put  | Interview Value |
| ------------------ | ---------------------------- | ---- | ---- | --------------- |
| Brute Force        | Array/List                   | O(n) | O(n) | Low             |
| Ordered Dictionary | HashMap + Ordered Map        | O(1) | O(1) | Good            |
| Optimal            | HashMap + Doubly Linked List | O(1) | O(1) | Best            |

# Pattern 1 — Brute Force Using List

## Idea

Maintain list of `(key,value)`.

Most recently used item kept at end.

When accessed:

* search linearly
* remove and append at end

---

## Operations

### get(key)

* scan list
* if found:

  * remove item
  * append to end
* else return -1

### put(key,value)

* scan list
* update if exists
* else append
* remove first element if capacity exceeded

---

## Complexity

| Operation | Complexity |
| --------- | ---------- |
| get       | O(n)       |
| put       | O(n)       |

---

## Code

```python
class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = []

    def get(self, key: int) -> int:

        for i, (k, v) in enumerate(self.cache):

            if k == key:
                self.cache.pop(i)
                self.cache.append((k, v))
                return v

        return -1

    def put(self, key: int, value: int) -> None:

        for i, (k, v) in enumerate(self.cache):

            if k == key:
                self.cache.pop(i)
                self.cache.append((key, value))
                return

        if len(self.cache) == self.capacity:
            self.cache.pop(0)

        self.cache.append((key, value))
```

# Pattern 2 — OrderedDict

## Idea

Python provides:

```python
collections.OrderedDict
```

It maintains insertion order.

Move recently used items to end.

---

## Complexity

| Operation | Complexity |
| --------- | ---------- |
| get       | O(1)       |
| put       | O(1)       |

---

## Code

```python
from collections import OrderedDict

class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = OrderedDict()

    def get(self, key: int) -> int:

        if key not in self.cache:
            return -1

        self.cache.move_to_end(key)

        return self.cache[key]

    def put(self, key: int, value: int) -> None:

        if key in self.cache:
            self.cache.move_to_end(key)

        self.cache[key] = value

        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)
```

# Pattern 3 — Optimal Interview Solution

# HashMap + Doubly Linked List

This is the classic interview solution.

---

# Core Idea

We need:

| Requirement        | Best DS            |
| ------------------ | ------------------ |
| Fast lookup by key | HashMap            |
| Fast deletion      | Doubly Linked List |
| Fast move-to-front | Doubly Linked List |

---

# Structure

```text
HashMap:
key -> node

DLL:
Most Recent <-> ... <-> Least Recent
```

---

# Why Doubly Linked List?

Because we need O(1):

* remove node
* insert node
* move node

Singly linked list cannot remove node in O(1).

---

# Node Structure

```python
class Node:

    def __init__(self, key, value):
        self.key = key
        self.value = value

        self.prev = None
        self.next = None
```

---

# Important Concept

## Most Recently Used (MRU)

Keep near HEAD.

## Least Recently Used (LRU)

Keep near TAIL.

---

# Dummy Nodes Technique

Use:

```text
head <-> tail
```

Dummy nodes simplify:

* insertion
* deletion
* edge cases

---

# Visual Flow

```text
head <-> tail
```

```text
head <-> 1 <-> tail
```

```text
head <-> 2 <-> 1 <-> tail
```


# Helper Functions

---

## Remove Node

```python
def remove(node):

    prev_node = node.prev
    next_node = node.next

    prev_node.next = next_node
    next_node.prev = prev_node
```

---

## Insert at Front

```python
def insert(node):

    node.next = head.next
    node.prev = head

    head.next.prev = node
    head.next = node
```

# Full Optimal Code

```python
class Node:

    def __init__(self, key, value):

        self.key = key
        self.value = value

        self.prev = None
        self.next = None


class LRUCache:

    def __init__(self, capacity: int):

        self.capacity = capacity
        self.cache = {}

        self.head = Node(0, 0)
        self.tail = Node(0, 0)

        self.head.next = self.tail
        self.tail.prev = self.head

    # Remove node
    def remove(self, node):

        prev_node = node.prev
        next_node = node.next

        prev_node.next = next_node
        next_node.prev = prev_node

    # Insert after head
    def insert(self, node):

        node.next = self.head.next
        node.prev = self.head

        self.head.next.prev = node
        self.head.next = node

    def get(self, key: int) -> int:

        if key not in self.cache:
            return -1

        node = self.cache[key]

        # move to front
        self.remove(node)
        self.insert(node)

        return node.value

    def put(self, key: int, value: int) -> None:

        if key in self.cache:

            old_node = self.cache[key]

            self.remove(old_node)

        node = Node(key, value)

        self.cache[key] = node

        self.insert(node)

        if len(self.cache) > self.capacity:

            # remove LRU
            lru = self.tail.prev

            self.remove(lru)

            del self.cache[lru.key]
```

# Why This is Optimal

Because:

* hashmap gives O(1) lookup
* doubly linked list gives O(1):

  * insertion
  * deletion
  * movement

Total:

```text
O(1) get
O(1) put
```

# Interview Discussion Points

## Why not only hashmap?

HashMap cannot track usage order efficiently.

---

## Why not queue?

Queue cannot remove middle node in O(1).

---

## Why DLL?

DLL allows:

* remove arbitrary node
* move arbitrary node

in constant time.
