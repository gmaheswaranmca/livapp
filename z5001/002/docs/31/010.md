# Car Fleet (Medium)

**Problem Summary**

You are given:

* `target` = destination position
* `position[i]` = current position of car `i`
* `speed[i]` = speed of car `i`

A faster car behind cannot pass a slower car ahead. If it catches up, they form a **fleet** and move together at the slower speed.

Return the number of fleets that reach the target.

---

# Pattern 1: Simulation (Brute Force)

## Idea

Continuously simulate car movements and merge fleets when cars meet.

## Steps

1. Move cars over time.
2. Detect collisions.
3. Merge fleets.
4. Count final fleets.

## Complexity

* Time: Very High (not practical)
* Space: O(n)

## Verdict

❌ Not suitable for interviews.

---

# Pattern 2: Sort + Stack

## Observation

For every car:

[
time = \frac{target-position}{speed}
]

Sort cars by position descending (nearest to target first).

If a car behind reaches the target earlier than the fleet ahead, it joins that fleet.

Use a stack to maintain fleet arrival times.

---

## Algorithm

1. Pair `(position, speed)`.
2. Sort by position descending.
3. Calculate arrival time.
4. Push time into stack.
5. If current time ≤ top fleet time:

   * Merge with fleet.
   * Remove current time.
6. Stack size = fleet count.

---

## Code

```python
from typing import List

class Solution:
    def carFleet(self, target: int,
                 position: List[int],
                 speed: List[int]) -> int:

        cars = sorted(zip(position, speed),
                      reverse=True)

        stack = []

        for pos, spd in cars:

            time = (target - pos) / spd

            stack.append(time)

            if len(stack) >= 2 and stack[-1] <= stack[-2]:
                stack.pop()

        return len(stack)
```

---

## Complexity

* Sorting: O(n log n)
* Traversal: O(n)

**Total: O(n log n)**

Space: O(n)

# Pattern 3: Sort + Monotonic Fleet Time (Optimized)

## Key Insight

We do not actually need a stack.

While moving from front car to back car:

* Maintain maximum fleet arrival time seen so far.
* If current car takes longer than fleet ahead:

  * It forms a new fleet.
* Otherwise:

  * It joins existing fleet.

---

## Visualization

```text
Target = 12

Position : [10,8,0,5,3]
Speed    : [2,4,1,1,3]

Times:

10 -> 1
8  -> 1
5  -> 7
3  -> 3
0  -> 12
```

Sorted by position descending:

```text
(10,1)
(8,1)
(5,7)
(3,3)
(0,12)
```

Process:

```text
fleet_time = 1
fleet_count = 1

1 <= 1  -> joins fleet

7 > 1   -> new fleet

3 <= 7  -> joins fleet

12 > 7  -> new fleet
```

Answer = 3 fleets

---

## Code

```python
from typing import List

class Solution:
    def carFleet(self, target: int,
                 position: List[int],
                 speed: List[int]) -> int:

        cars = sorted(zip(position, speed),
                      reverse=True)

        fleets = 0
        max_time = 0

        for pos, spd in cars:

            time = (target - pos) / spd

            if time > max_time:
                fleets += 1
                max_time = time

        return fleets
```

---

## Complexity

* Time: O(n log n)
* Space: O(1) (excluding sorting)

# Pattern Comparison

| Pattern               | Idea                   | Time       | Space | Interview Use |
| --------------------- | ---------------------- | ---------- | ----- | ------------- |
| Simulation            | Physically move cars   | Very High  | O(n)  | ❌             |
| Sort + Stack          | Maintain fleet times   | O(n log n) | O(n)  | ✅             |
| Sort + Monotonic Time | Track max arrival time | O(n log n) | O(1)  | ✅✅ Best       |

---

# Recognition Pattern

Use **Sort by Position + Monotonic Processing** when:

* Objects move toward a destination.
* Overtaking is not allowed.
* Merging/grouping happens upon catching up.
* Need number of groups/fleets formed.
* Cars/trains/packets/people merge based on arrival times.

Examples:

* Car Fleet
* Fleet Formation
* Train Compartment Merging
* Collision Group Counting
* Moving Objects Grouping Problems

# Optimized Pattern for Interviews

### Sort by Position Descending + Monotonic Fleet Arrival Time

```python
from typing import List

class Solution:
    def carFleet(self, target: int,
                 position: List[int],
                 speed: List[int]) -> int:

        cars = sorted(zip(position, speed),
                      reverse=True)

        fleets = 0
        fleet_time = 0

        for pos, spd in cars:

            arrival_time = (target - pos) / spd

            if arrival_time > fleet_time:
                fleets += 1
                fleet_time = arrival_time

        return fleets
```

### Why this is optimal?

* Sorting is unavoidable → O(n log n)
* Single pass after sorting
* Constant extra space
* Cleanest interview explanation
* Standard solution expected by Amazon, Google, Meta, and Microsoft interviewers.
