# Problem: Integer to Roman

Convert an integer into its Roman numeral representation.

**Asked By:** Amazon, Google, Meta, Microsoft
**Difficulty:** Medium

---

# Solution Patterns

## Pattern 1: Repeated Symbol Subtraction (Brute Force)

### Idea

Keep subtracting the largest possible Roman value and append its symbol.

Example:

```
58

50 -> L
5  -> V
3  -> III

Result = LVIII
```

### Complexity

* Time: O(Value)
* Space: O(1)

### Code

```python
def intToRoman(num):
    result = ""

    while num >= 1000:
        result += "M"
        num -= 1000

    while num >= 500:
        result += "D"
        num -= 500

    while num >= 100:
        result += "C"
        num -= 100

    while num >= 50:
        result += "L"
        num -= 50

    while num >= 10:
        result += "X"
        num -= 10

    while num >= 5:
        result += "V"
        num -= 5

    while num >= 1:
        result += "I"
        num -= 1

    return result
```

### Limitation

Does not handle subtractive cases:

```
4  -> IV
9  -> IX
40 -> XL
90 -> XC
400 -> CD
900 -> CM
```

# Pattern 2: Greedy with Complete Roman Mapping

### Idea

Store every Roman numeral value including subtractive forms.

```
1000 -> M
900  -> CM
500  -> D
400  -> CD
100  -> C
90   -> XC
50   -> L
40   -> XL
10   -> X
9    -> IX
5    -> V
4    -> IV
1    -> I
```

Always pick the largest value not exceeding the current number.

---

### Example

```
1994

1000 -> M
900  -> CM
90   -> XC
4    -> IV

Result = MCMXCIV
```

---

### Complexity

* Time: O(13) ≈ O(1)
* Space: O(1)

### Code

```python
def intToRoman(num):
    values = [
        1000, 900, 500, 400,
        100, 90, 50, 40,
        10, 9, 5, 4, 1
    ]

    romans = [
        "M", "CM", "D", "CD",
        "C", "XC", "L", "XL",
        "X", "IX", "V", "IV", "I"
    ]

    result = []

    for i in range(len(values)):
        while num >= values[i]:
            result.append(romans[i])
            num -= values[i]

    return "".join(result)
```

# Pattern 3: Greedy Using Division (Optimized)

### Idea

Instead of repeatedly subtracting:

```python
while num >= value:
```

calculate how many times a Roman symbol appears.

```
count = num // value
```

Append symbol `count` times.

---

### Example

```
num = 3888

1000 -> 3 times => MMM
500  -> 1 time  => D
100  -> 3 times => CCC
50   -> 1 time  => L
10   -> 3 times => XXX
5    -> 1 time  => V
1    -> 3 times => III

Result = MMMDCCCLXXXVIII
```

---

### Complexity

* Time: O(13) ≈ O(1)
* Space: O(1)

### Code

```python
def intToRoman(num):
    pairs = [
        (1000, "M"),
        (900, "CM"),
        (500, "D"),
        (400, "CD"),
        (100, "C"),
        (90, "XC"),
        (50, "L"),
        (40, "XL"),
        (10, "X"),
        (9, "IX"),
        (5, "V"),
        (4, "IV"),
        (1, "I")
    ]

    result = []

    for value, symbol in pairs:
        count = num // value

        if count:
            result.append(symbol * count)
            num %= value

    return "".join(result)
```

# Pattern 4: Digit-by-Digit Lookup Table

### Idea

Roman numerals have fixed representations for each digit place.

Create lookup tables:

```
Ones
Tens
Hundreds
Thousands
```

Build answer directly.

---

### Example

```
1994

Thousands = M
Hundreds  = CM
Tens      = XC
Ones      = IV

Result = MCMXCIV
```

---

### Complexity

* Time: O(1)
* Space: O(1)

### Code

```python
def intToRoman(num):
    thousands = [
        "", "M", "MM", "MMM"
    ]

    hundreds = [
        "", "C", "CC", "CCC",
        "CD", "D", "DC", "DCC",
        "DCCC", "CM"
    ]

    tens = [
        "", "X", "XX", "XXX",
        "XL", "L", "LX", "LXX",
        "LXXX", "XC"
    ]

    ones = [
        "", "I", "II", "III",
        "IV", "V", "VI", "VII",
        "VIII", "IX"
    ]

    return (
        thousands[num // 1000] +
        hundreds[(num % 1000) // 100] +
        tens[(num % 100) // 10] +
        ones[num % 10]
    )
```

# Pattern Comparison

| Pattern              | Time     | Space | Interview Value |
| -------------------- | -------- | ----- | --------------- |
| Repeated Subtraction | O(Value) | O(1)  | Low             |
| Greedy Mapping       | O(1)     | O(1)  | Very High       |
| Greedy Division      | O(1)     | O(1)  | High            |
| Lookup Tables        | O(1)     | O(1)  | Highest         |

# Optimized Pattern

## Digit-by-Digit Lookup Table

Why?

* True O(1) solution.
* No loops over symbols.
* No repeated subtraction.
* Very clean implementation.
* Commonly considered the most elegant solution for LeetCode 12.

```python
def intToRoman(num):
    thousands = ["", "M", "MM", "MMM"]

    hundreds = [
        "", "C", "CC", "CCC",
        "CD", "D", "DC", "DCC",
        "DCCC", "CM"
    ]

    tens = [
        "", "X", "XX", "XXX",
        "XL", "L", "LX", "LXX",
        "LXXX", "XC"
    ]

    ones = [
        "", "I", "II", "III",
        "IV", "V", "VI", "VII",
        "VIII", "IX"
    ]

    return (
        thousands[num // 1000] +
        hundreds[(num % 1000) // 100] +
        tens[(num % 100) // 10] +
        ones[num % 10]
    )
```

### Interview Recommendation

1. Explain the Greedy Mapping approach first (most intuitive).
2. Then mention the Lookup Table approach as a constant-time optimization.
3. Implement whichever the interviewer prefers; both are accepted and optimal for the constraint `1 <= num <= 3999`.
