# Time Needed to Buy Tickets (LeetCode 2073)

**Difficulty:** Easy
**Companies:** Amazon, Microsoft, Bloomberg, Google

## Problem

You are given an integer array `tickets` where `tickets[i]` is the number of tickets person `i` wants to buy.

People stand in a queue:

* The person at the front buys **one ticket** and takes **1 second**.
* If they still need more tickets, they move to the end of the queue.
* Otherwise, they leave the queue.

Return the time required for the person at index `k` to finish buying all their tickets.

### Example

```text
Input:
tickets = [2,3,2], k = 2

Output:
6
```

Queue simulation:

```text
[2,3,2]
[1,3,2]  -> 1 sec
[3,2,1]  -> 2 sec
[2,1,2]  -> 3 sec
[1,2,1]  -> 4 sec
[2,1]    -> 5 sec
[1]      -> 6 sec
```

Person `k=2` finishes after 6 seconds.

---

# Solution Patterns

## Pattern 1: Queue Simulation (Brute Force)

### Idea

Simulate exactly what the problem states.

Store:

```python
(ticket_count, index)
```

in a queue.

Process one ticket per second until person `k` finishes.

### Algorithm

1. Push all people into queue.
2. Pop front person.
3. Buy one ticket.
4. Increment time.
5. If person's tickets become zero:

   * If index == k, return time.
6. Otherwise push back into queue.

### Code

```python
from collections import deque

class Solution:
    def timeRequiredToBuy(self, tickets, k):
        q = deque()

        for i, t in enumerate(tickets):
            q.append((t, i))

        time = 0

        while q:
            count, idx = q.popleft()

            count -= 1
            time += 1

            if count == 0:
                if idx == k:
                    return time
            else:
                q.append((count, idx))
```

### Complexity

```text
Time  : O(total tickets)
Space : O(n)
```

where

```text
total tickets = sum(tickets)
```

# Pattern 2: Mathematical Counting (Optimized)

### Key Observation

Let:

```python
target = tickets[k]
```

For every person:

### Person before or at k

They can buy at most:

```python
min(tickets[i], target)
```

tickets before person `k` finishes.

### Person after k

They can buy at most:

```python
min(tickets[i], target - 1)
```

because once `k` buys the last ticket, the process stops.

---

### Example

```python
tickets = [2,3,2]
k = 2
target = 2
```

Index ≤ k:

```text
Person 0: min(2,2)=2
Person 1: min(3,2)=2
Person 2: min(2,2)=2
```

Total:

```text
2+2+2 = 6
```

Answer = 6

---

### Code

```python
class Solution:
    def timeRequiredToBuy(self, tickets, k):
        target = tickets[k]
        time = 0

        for i in range(len(tickets)):
            if i <= k:
                time += min(tickets[i], target)
            else:
                time += min(tickets[i], target - 1)

        return time
```

---

### Complexity

```text
Time  : O(n)
Space : O(1)
```

# Pattern 3: Direct Formula Version

Same idea as Pattern 2, written compactly.

```python
class Solution:
    def timeRequiredToBuy(self, tickets, k):
        target = tickets[k]

        return sum(
            min(tickets[i], target if i <= k else target - 1)
            for i in range(len(tickets))
        )
```

### Complexity

```text
Time  : O(n)
Space : O(1)
```

# Optimized Solution

```python
class Solution:
    def timeRequiredToBuy(self, tickets, k):
        target = tickets[k]
        time = 0

        for i in range(len(tickets)):
            if i <= k:
                time += min(tickets[i], target)
            else:
                time += min(tickets[i], target - 1)

        return time
```

### Why this is optimal?

* No queue simulation.
* Single traversal.
* Constant extra space.
* Uses the observation that every person contributes a predictable number of ticket purchases before person `k` finishes.

```text
Time  : O(n)
Space : O(1)
```

### Pattern Recognition

When you see:

* Queue rotation
* "Process until a specific person finishes"
* Need only the final count/time

Think:

```text
Simulation
        ↓
Count each participant's contribution
        ↓
Mathematical / Observation-Based Optimization
```

This is the most commonly expected interview solution for **Time Needed to Buy Tickets**.
