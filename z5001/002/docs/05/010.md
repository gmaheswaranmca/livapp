# Dota2 Senate (LeetCode 649)

**Problem:**
Given a senate string consisting of `'R'` (Radiant) and `'D'` (Dire), senators take turns banning opponents. Each active senator can ban one senator from the opposing party. The process continues until only one party remains.

---

# Pattern Analysis

## Pattern 1: Direct Simulation (Brute Force)

### Idea

* Maintain active/inactive senators.
* Simulate each round.
* When a senator gets a turn, ban the next available opponent.

### Steps

1. Iterate through senators repeatedly.
2. Find next available opponent.
3. Mark opponent as banned.
4. Continue until one party remains.

### Complexity

* **Time:** O(N²)
* **Space:** O(N)

### Why it is not optimal?

Finding the next opponent repeatedly causes many scans.

---

# Pattern 2: Queue Simulation (Recommended)

## Core Observation

Think of the senate as a **circular queue**.

* Radiant senators compete with Dire senators.
* Whoever appears earlier gets to ban the other.
* After acting, the winning senator returns to the next round.

Store indices of:

* Radiant senators in one queue
* Dire senators in another queue

---

## Example

```text
senate = "RDD"

Radiant Queue = [0]
Dire Queue = [1,2]
```

Compare front senators:

```text
0 vs 1

0 wins because 0 < 1
Radiant bans Dire at position 1
Radiant returns at 0 + n = 3
```

Queues:

```text
Radiant = [3]
Dire = [2]
```

Next:

```text
3 vs 2

Dire wins
Dire returns at 2 + n = 5
```

Queues:

```text
Radiant = []
Dire = [5]
```

Dire wins.

---

# Why Adding n Works?

Suppose:

```text
n = 5
```

Senator at index:

```text
1
```

After completing the current round, he should appear in the next cycle.

```text
1 + 5 = 6
```

This preserves circular ordering.

# Optimized Solution (Queue Pattern)

```python
from collections import deque

class Solution:
    def predictPartyVictory(self, senate: str) -> str:

        n = len(senate)

        radiant = deque()
        dire = deque()

        for i, ch in enumerate(senate):
            if ch == 'R':
                radiant.append(i)
            else:
                dire.append(i)

        while radiant and dire:

            r = radiant.popleft()
            d = dire.popleft()

            if r < d:
                radiant.append(r + n)
            else:
                dire.append(d + n)

        return "Radiant" if radiant else "Dire"
```

# Alternative Pattern: Pending Ban Counters

### Idea

Keep track of:

* pending bans against Radiant
* pending bans against Dire

Process senators in circular order.

### Complexity

* **Time:** O(N²) in repeated rounds
* **Space:** O(N)

Less intuitive and less efficient than queue-index simulation.

# Interview Answer

> Use two queues to store the indices of Radiant and Dire senators. At each step, compare the front indices. The senator with the smaller index acts first and bans the opponent. The winner is reinserted into its queue with index `current_index + n`, representing participation in the next round. Continue until one queue becomes empty. This yields an O(N) time and O(N) space solution.
