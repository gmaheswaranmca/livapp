*🚀 Coding Interview Questions with Answers — Part 7*

*🌐 Full-Stack & System Design Basics*

*🚀 61. Explain how a web request travels from browser to server and back.*
When you enter a URL in the browser, many steps happen behind the scenes.

*🔹 Complete Flow*
Browser → DNS → Server → Database → Response → Browser

*🔹 Step-by-Step Process*
*1️⃣ User Enters URL*
Example:
https://example.com
*2️⃣ DNS Lookup*
DNS converts domain to IP address
Example: example.com → 192.168.1.1

*3️⃣ TCP Connection*
Browser creates connection with server.
HTTPS additionally uses TLS/SSL Handshake

*4️⃣ HTTP Request Sent*
Example:
GET /home HTTP/1.1
*5️⃣ Server Processes Request*
Backend may:
- Run application logic
- Query database
- Authenticate user

*6️⃣ Server Sends Response*
Example: HTML / JSON / CSS / JS

*7️⃣ Browser Renders Page*
Browser:
- Parses HTML
- Applies CSS
- Executes JavaScript

*🔹 Interview Tip*
This is one of the most frequently asked full-stack interview questions.

*🚀 62. What is the difference between HTTP and HTTPS?*

*🔹 HTTP*
- HyperText Transfer Protocol
- Data transferred in plain text
- Not secure
- Port 80
- No encryption
- Vulnerable

*🔹 HTTPS*
- HTTP + SSL/TLS Encryption
- Data encrypted
- Secure communication
- Port 443
- Encryption enabled
- Safer

*🔹 Why HTTPS Matters*
✅ Protects passwords
✅ Prevents man-in-the-middle attacks
✅ Required for payment systems

*🔹 Interview Tip*
HTTPS improves both security and SEO rankings.

*🚀 63. What is DNS and how does it work?*
DNS: Domain Name System
Acts like the internet’s phonebook.

*🔹 Example*
google.com → 142.250.183.14

*🔹 DNS Flow*
1. Browser cache
2. OS cache
3. ISP DNS resolver
4. Root server
5. TLD server
6. Authoritative DNS server

*🔹 Types of DNS Records*
- *A*: IPv4 address
- *AAAA*: IPv6 address
- *CNAME*: Alias
- *MX*: Mail server

*🔹 Interview Tip*
DNS is essential knowledge for backend/system-design interviews.

*🚀 64. What is the role of a CDN?*
CDN: Content Delivery Network
Distributes content across global servers.

*🔹 Goal*
Reduce latency and server load

*🔹 Example*
Without CDN: India user → US server
With CDN: India user → Nearby CDN server

*🔹 CDN Stores*
✅ Images
✅ Videos
✅ CSS/JS
✅ Static assets

*🔹 Benefits*
✅ Faster loading
✅ Lower latency
✅ Better scalability
✅ DDoS protection

*🔹 Interview Tip*
CDNs are heavily used in scalable applications.

*🚀 65. How do you reduce latency in a web application?*

Latency = response delay.

*🔹 Common Techniques*
✅ *Use CDN*: Serve assets closer to users
✅ *Database Indexing*: Faster queries
✅ *Caching*: Store frequently used data
✅ *Compression*: Use Gzip / Brotli
✅ *Lazy Loading*: Load resources only when needed
✅ *Reduce API Calls*: Combine requests efficiently
✅ *Load Balancing*: Distribute traffic
✅ *Async Processing*: Use queues/background jobs

*🔹 Interview Tip*
Performance optimization is a key system-design topic.

*🚀 66. What is caching and where do you place it?*
Caching stores frequently used data temporarily.

*🔹 Types of Cache*
*🔹 Browser Cache*: Stores static resources locally
*🔹 CDN Cache*: Caches content globally
*🔹 Server Cache*: Examples: Redis, Memcached
*🔹 Database Cache*: Stores query results
*🔹 Application Cache*: Stores computed values

*🔹 Benefits*
✅ Faster response
✅ Reduced DB load
✅ Better scalability

*🔹 Common Tools*
- Redis
- Memcached

*🔹 Interview Tip*
Caching is one of the most important scalability concepts.

*🚀 67. What is the difference between horizontal and vertical scaling?*

*🔹 Vertical Scaling*
- Upgrade single server
- Example: More RAM, Better CPU
- One server
- Limited scalability
- Easier setup

*🔹 Horizontal Scaling*
- Add more servers
- Multiple servers
- Highly scalable
- More complex

*🔹 Real-World Example*
Vertical → Bigger machine
Horizontal → Multiple machines behind load balancer

*🔹 Interview Tip*
Modern scalable systems usually prefer horizontal scaling.

*🚀 68. What is load balancing and how does it work?*
Load balancer distributes traffic across servers.

*🔹 Goal*
Prevent single-server overload

*🔹 Architecture*
Users → Load Balancer → Multiple Servers

*🔹 Algorithms*
- *Round Robin*: Sequential distribution
- *Least Connections*: Least busy server
- *IP Hashing*: Based on client IP

*🔹 Benefits*
✅ High availability
✅ Scalability
✅ Fault tolerance

*🔹 Popular Load Balancers*
- NGINX
- HAProxy

*🚀 69. What is rate limiting and how do you implement it?*
Rate limiting controls request frequency.

*🔹 Example*
100 requests/minute/user

*🔹 Why Important?*
✅ Prevent abuse
✅ Prevent DDoS attacks
✅ Protect APIs

*🔹 Common Algorithms*
- *Token Bucket*: Tokens refill over time
- *Leaky Bucket*: Fixed processing rate
- *Fixed Window*: Count requests in interval
- *Sliding Window*: More accurate window

*🔹 Common Tools*
- Redis
- NGINX

*🔹 Interview Tip*
Rate limiting is heavily discussed in API design interviews.

*🚀 70. How do you design a URL shortener system?*

Example:
https://example.com/abc123

*🔹 Core Components*
✅ *URL Generator*: Generate unique short code
✅ *Database*: Store short URL → original URL mapping
✅ *Redirect Service*: Redirect short URL to original URL
✅ *Caching Layer*: Cache popular URLs
✅ *Load Balancer*: Handle high traffic

*🔹 High-Level Architecture*
User → API → DB/Cache → Redirect

*🔹 Challenges*
✅ Collision handling
✅ Scalability
✅ Analytics tracking
✅ Expiration links

*🔹 Popular Real-World Examples*
- Bitly
- TinyURL

*🔹 Interview Tip*
URL shortener is one of the most common beginner system-design questions.
