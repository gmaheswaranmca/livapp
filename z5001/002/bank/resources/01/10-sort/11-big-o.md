📊 *Big O Notation Cheatsheet* 🚀  

Understand how your code performs as data grows!

🔹 *O(1) – Constant Time*  
✅ Time is the same no matter the input size  
📌 Example: Accessing an element in a hash table  
💡 Fastest possible performance

🔹 *O(log n) – Logarithmic Time*  
✅ Performance grows slowly even with large input  
📌 Example: Binary search on a sorted array  
💡 Very efficient for large data sets

🔹 *O(n) – Linear Time*  
✅ Time grows in direct proportion to input  
📌 Example: Looping through an array  
💡 Good for simple iterations

🔹 *O(n log n) – Linearithmic Time*  
✅ Grows faster than linear but better than quadratic  
📌 Example: Efficient sorting like Merge Sort, Quick Sort  
💡 Common in real-world sorting algorithms

🔹 *O(n²) – Quadratic Time*  
❌ Time grows with square of input size  
📌 Example: Bubble sort, selection sort  
💡 Avoid for large inputs

🔹 *O(n³) – Cubic Time*  
❌ Time grows with cube of input size  
📌 Example: Triple nested loops  
💡 Very slow for large n

🔹 *O(2ⁿ) – Exponential Time*  
⚠️ Time doubles with each input addition  
📌 Example: Recursive Fibonacci  
💡 Impractical for even moderate inputs

🔹 *O(n!) – Factorial Time*  
⚠️ Time grows factorially with input
📌 Example: Solving Traveling Salesman with brute force  
💡 Used in brute-force permutations or combinations

🧠 *Tips:*  
✅ Prefer O(1) > O(log n) > O(n) > O(n log n)  
❌ Avoid O(n²), O(2ⁿ), O(n!) unless absolutely necessary  
✅ Use the right data structures & algorithms
