will our editor throw any syntax errors during writing code

---

Yes — absolutely. Your editor can show syntax errors LIVE while the student types, just like Visual Studio Code or Monaco Editor.

And you should definitely implement it.

# Two Types of Errors

## 1. Editor Syntax Errors (Realtime)

While typing:

```python id="u1f1mv"
def add(
```

editor immediately highlights:

* missing `)`
* invalid indentation
* invalid tokens

This is FAST and local.

---

## 2. Runtime Errors (During Execution)

When user clicks Run:

```python id="4v3s9t"
print(x)
```

Then runtime gives:

```text id="ysu3b6"
NameError: name 'x' is not defined
```

This comes from Pyodide execution.

---

# Simplest and BEST Initial Solution

Use Python AST parsing through Pyodide worker.

Flow:

```text id="9rv4pi"
Editor change
     ↓ debounce
Worker
     ↓
ast.parse(code)
     ↓
Return syntax errors
     ↓
Show markers in Monaco
```

This is VERY practical.

---

# Example

## User Types

```python id="rqb9a3"
def add(
```

## Pyodide Check

```python id="cl17y2"
import ast

ast.parse(code)
```

Throws:

```text id="1ngmzx"
SyntaxError: '(' was never closed
```

Then you mark line in editor.

# Monaco Marker Example

```js id="gl4lxt"
monaco.editor.setModelMarkers(model, "python", [
  {
    startLineNumber: 1,
    startColumn: 9,
    endLineNumber: 1,
    endColumn: 10,
    message: "Expected ')'",
    severity: monaco.MarkerSeverity.Error
  }
]);
```

This creates:

* red underline
* error hover
* side gutter mark

Exactly like VS Code.

---

# IMPORTANT — Debounce Checks

Do NOT parse on every keystroke.

Use:

```js id="f3cim7"
setTimeout(() => {
   validateCode()
}, 300)
```

Otherwise:

* worker overload
* lag
* battery drain
