# STEP 12 : Runtime Design

Every runtime MUST follow:

```javascript
class Runtime {

    init()

    run(code)

    restart()

    destroy()

}
```

So:

```text
PyodideRuntime

WebRRuntime

CppRuntime

JSRuntime
```

all look identical to the editor.

The editor never knows:

```text
How Pyodide works

How WebR works

How C++ compiles
```

This separation is extremely important.

# STEP 13 : Development Order

We will implement:

```text
1 LanguageSelector

2 MonacoEditorWrapper

3 OutputPanel

4 Toolbar

5 JS Runtime

6 Pyodide Runtime

7 WebR Runtime

8 RuntimeFactory

9 KernelManager

10 C++ Runtime

11 Problem Page

12 Judge System
```

This order minimizes complexity and keeps the application runnable at every stage.

**I suggest our next step should be:** **Build the editor UI completely first** (LanguageSelector + MonacoEditorWrapper + OutputPanel + Toolbar), without any runtime yet. Once the UI is stable, we will connect JavaScript execution first, then Python, then R, and finally C++.
