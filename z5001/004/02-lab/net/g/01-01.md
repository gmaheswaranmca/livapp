For teaching, keep it as simple as possible. First demonstrate a **single-threaded server**. Let students observe that only one client can be served at a time. Then introduce threading.

---

# 1. Server (Single Client)

```python
# server.py

import socket

HOST = "127.0.0.1"
PORT = 5000

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

server.bind((HOST, PORT))

server.listen(5)

print(f"Server listening on {HOST}:{PORT}")

while True:
    print("\nWaiting for a client...")

    client, address = server.accept()

    print("Connected:", address)

    while True:
        data = client.recv(1024)

        if not data:
            break

        message = data.decode()

        print("Client:", message)

        reply = input("Server Reply: ")

        client.send(reply.encode())

    client.close()

    print("Client disconnected")
```

---

# 2. Client

```python
# client.py

import socket

HOST = "127.0.0.1"
PORT = 5000

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

client.connect((HOST, PORT))

print("Connected to server")

while True:

    msg = input("You: ")

    if msg.lower() == "exit":
        break

    client.send(msg.encode())

    reply = client.recv(1024)

    print("Server:", reply.decode())

client.close()
```

# Demonstration Problem

Open another terminal.

```
python client.py
```

Students expect

```
Connected
```

Instead...

It hangs.

Nothing happens.

Why?

Because the server is here

```python
while True:

    data = client.recv(1024)
```

The server is **busy serving Client A**.

It never returns to

```python
accept()
```

Therefore

```
Client A  ---> Talking

Client B  ---> Waiting

Client C  ---> Waiting
```

Server state

```
accept()

↓

Client A accepted

↓

recv()

↓

recv()

↓

recv()

↓

recv()

↓

Never reaches accept()
```

This clearly shows the limitation of a single-threaded server.

# Explain

A process has

* One CPU execution flow
* One instruction pointer

So it can execute

```
accept()

OR

recv()

NOT BOTH
```

Hence

```
Client A
↓

recv()

↓

Server blocked

↓

accept() never executes

↓

Client B waits
```

# Threaded Version

Now students immediately understand why threads exist.

```python
accept()

↓

Client connected

↓

Create Thread

↓

Thread handles recv()

↓

Main thread returns to accept()
```

Diagram

```
Main Thread

accept()

|

+------ Client A Thread

|

accept()

|

+------ Client B Thread

|

accept()

|

+------ Client C Thread
```

Now

```
Client A
Talking

Client B
Talking

Client C
Talking
```

simultaneously.
