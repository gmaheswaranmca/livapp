The flow can be:

1. Single-threaded server
2. Observe the problem (Client B and C wait)
3. Ask students: "How can we keep accepting new clients while talking to Client A?"
4. Introduce threads.
5. Convert the server with minimal changes.

## Threaded Server

```python
# threaded_server.py

import socket
import threading

HOST = "127.0.0.1"
PORT = 5000


def handle_client(client, address):
    print(f"{address} connected")

    while True:
        try:
            data = client.recv(1024)

            if not data:
                break

            message = data.decode()

            print(f"{address}: {message}")

            reply = input(f"Reply to {address}: ")

            client.send(reply.encode())

        except:
            break

    client.close()
    print(f"{address} disconnected")


server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

server.bind((HOST, PORT))

server.listen(5)

print("Server started...")

while True:

    client, address = server.accept()

    thread = threading.Thread(
        target=handle_client,
        args=(client, address)
    )

    thread.start()
```

The **client code remains exactly the same**.

---

## What changed?

Only three things:

### 1. Import threading

```python
import threading
```

---

### 2. Move client handling into a function

```python
def handle_client(client, address):
    ...
```

Instead of handling the client directly in the main loop.

---

### 3. Create a thread

```python
thread = threading.Thread(
    target=handle_client,
    args=(client, address)
)

thread.start()
```

Now the main thread immediately goes back to:

```python
client, address = server.accept()
```

while the new thread continues handling that client.

---

## Execution Flow

```
Main Thread

accept()
    │
    ├── Client A
    │      │
    │      └── Thread A
    │
accept()
    │
    ├── Client B
    │      │
    │      └── Thread B
    │
accept()
    │
    ├── Client C
    │      │
    │      └── Thread C
```

Each client gets its own thread.

---

### One teaching note

Using `input()` inside each client thread is fine for demonstrating threading, but it's not ideal for a multi-client server because multiple threads may prompt for console input at the same time. For a cleaner demonstration, have the server automatically echo the client's message:

```python
reply = f"Server received: {message}"
client.send(reply.encode())
```

This lets all clients communicate concurrently without competing for keyboard input, making the effect of threading much clearer.
