Yes. This design is much cleaner because it teaches **three independent threads of execution**:

1. **Client conversation** (can end by either side)
2. **Server client-handler thread**
3. **Server admin thread** (controls server shutdown)

Use two protocol messages:

* `END` → End only this conversation.
* `SHUTDOWN` → Stop the entire server.

---

## Protocol

| Message     | Meaning                             |
| ----------- | ----------------------------------- |
| Normal text | Continue conversation               |
| `END`       | End this client conversation        |
| `SHUTDOWN`  | Admin command (server console only) |

---

# Server

```python
import socket
import threading

HOST = "127.0.0.1"
PORT = 5000

clients = []
running = True


def handle_client(client, address):
    print(f"{address} connected")
    clients.append(client)

    try:
        while running:

            data = client.recv(1024)

            if not data:
                break

            message = data.decode()

            print(f"{address}: {message}")

            # Client ends conversation
            if message.upper() == "END":
                client.send("END".encode())
                break

            reply = input(f"Reply to {address}: ")

            client.send(reply.encode())

            # Server ends conversation
            if reply.upper() == "END":
                break

    except:
        pass

    if client in clients:
        clients.remove(client)

    client.close()
    print(f"{address} disconnected")


def admin_console():
    global running

    while running:

        cmd = input("Admin> ")

        if cmd.upper() == "SHUTDOWN":

            running = False

            print("Stopping server...")

            for c in clients:
                try:
                    c.send("SERVER_SHUTDOWN".encode())
                    c.close()
                except:
                    pass

            server.close()
            break


server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

server.bind((HOST, PORT))
server.listen(5)

threading.Thread(target=admin_console, daemon=True).start()

print("Server started...")

while running:

    try:
        client, address = server.accept()

        threading.Thread(
            target=handle_client,
            args=(client, address),
            daemon=True
        ).start()

    except:
        break

print("Server stopped.")
```

# Client

```python
import socket

HOST = "127.0.0.1"
PORT = 5000

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

client.connect((HOST, PORT))

print("Connected")

while True:

    msg = input("You: ")

    client.send(msg.encode())

    # Client requested end
    if msg.upper() == "END":
        print("Conversation ended.")
        break

    reply = client.recv(1024)

    if not reply:
        break

    reply = reply.decode()

    # Server ended conversation
    if reply == "END":
        print("Server ended the conversation.")
        break

    # Entire server shutting down
    if reply == "SERVER_SHUTDOWN":
        print("Server is shutting down.")
        break

    print("Server:", reply)

client.close()

print("Disconnected")
```

## Demonstration Scenarios

### Scenario 1: Client ends the conversation

```
Client : Hello
Server : Hi

Client : END

Conversation ended.
```

Only that client disconnects. The server continues running.

---

### Scenario 2: Server ends the conversation

```
Client : Hello

Server Reply : END
```

Client receives:

```
Server ended the conversation.
Disconnected.
```

Only that client's session ends.

---

### Scenario 3: Administrator shuts down the server

On the server console:

```
Admin> SHUTDOWN
```

All connected clients receive:

```
Server is shutting down.
Disconnected.
```

The listening socket is closed, all client sockets are closed, and the server exits.

This version clearly demonstrates the difference between **ending a conversation** (`END`) and **stopping the entire service** (`SHUTDOWN`), which is a useful distinction when teaching network protocol design.
