Given your audience and the time available, I would treat this as a **"Build Along Workshop"** rather than a traditional course.

Your job is **not** to make every student type every line of code. Your job is to make sure everyone leaves understanding the concepts and with working examples they can use later.

# During every session

Follow the same rhythm:

1. Explain the problem (5–10 min).
2. Explain the API you'll use (5–10 min).
3. Live-code the core solution (10–15 min).
4. Run it and demonstrate different scenarios (10–15 min).
5. Answer questions and summarize (5 min).

This keeps the class moving while ensuring participants see both the reasoning and the working code.

## What you should prepare before class

Prepare everything in advance:

* A slide deck (15–20 slides).
* One repository with all examples.
* A `starter` version and a `completed` version for each topic.
* A few diagrams (socket flow, threading, event loop).
* Multiple terminals ready for demonstrations.
* Sample outputs and checkpoints in case of typing mistakes or environment issues.

For an 8-hour corporate workshop, this structure is practical, covers the advertised syllabus, and gives participants a clear understanding of when and how to use each module without getting bogged down in lengthy lab exercises.
