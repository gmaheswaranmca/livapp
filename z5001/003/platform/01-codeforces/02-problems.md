To become **world-class (Codeforces 3000+)**, there is no fixed list of problems. The goal is to develop the ability to solve **new, unseen problems under time pressure**.

### Stage 1: Foundation (0–1400)

Master basic data structures and algorithms.

Topics:

* Arrays
* Strings
* Sorting
* Binary Search
* Recursion
* Linked Lists
* Stack
* Queue
* Hashing
* Basic Math
* Prefix Sum
* Two Pointers

Target:

* Solve **200–300 problems**
* Reach Codeforces **1200–1400**

Platforms:

* [Codeforces](https://codeforces.com?utm_source=chatgpt.com)
* [LeetCode](https://leetcode.com?utm_source=chatgpt.com)

---

### Stage 2: Intermediate (1400–1800)

Learn common competitive programming patterns.

Topics:

* Greedy
* Sliding Window
* Monotonic Stack
* Binary Search on Answer
* BFS
* DFS
* Trees
* Basic DP
* Bit Manipulation

Target:

* Solve **500–800 problems total**
* Reach Codeforces **1600–1800**

---

### Stage 3: Advanced (1800–2200)

This is where many programmers get stuck.

Topics:

* Advanced DP
* Graph Algorithms
* Dijkstra
* Floyd Warshall
* Topological Sort
* DSU (Union Find)
* Segment Tree
* Fenwick Tree
* Sparse Table
* Trie

Target:

* Solve **1000–1500 problems total**
* Reach Codeforces **1900–2200**

---

### Stage 4: Expert to Candidate Master (2200–2600)

Now you focus on difficult contest problems.

Topics:

* Tree DP
* Digit DP
* Rerooting
* LCA
* Heavy Light Decomposition
* String Algorithms
* KMP
* Z Algorithm
* Rolling Hash
* Network Flow
* Matching

Target:

* Solve **1500–2500 problems**
* Participate in contests regularly

---

### Stage 5: International Master to Grandmaster (2600–3000)

At this level:

* Almost every basic algorithm is already known.
* The challenge is combining multiple concepts.
* Problem-solving creativity becomes more important than knowledge.

Topics:

* Advanced Graph Theory
* Game Theory
* FFT
* Computational Geometry
* Probability DP
* Inclusion-Exclusion
* Advanced Data Structures

Target:

* Thousands of hours of practice.
* Hundreds of difficult contests.

### The biggest mistake

Many people solve:

* 100 Easy LeetCode problems
* 100 Medium LeetCode problems

and think they're becoming competitive programmers.

Competitive programming growth comes mainly from:

1. Regular contests.
2. Upsolving problems you couldn't solve.
3. Learning editorials deeply.
4. Revisiting difficult problems after a few weeks.

A common path among elite competitors is:

> Contest → Fail on a problem → Read editorial → Reimplement → Solve similar problems → Contest again.

That cycle, repeated hundreds of times, is what eventually produces world-class competitors.
